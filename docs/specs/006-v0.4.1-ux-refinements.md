# UsageDashboard v0.4.1 交互体验精修规范（检查更新微动画、登录链接复制与提供方图标下拉）

本规范针对 `v0.4.0` 实机体验中暴露的 3 处交互细节进行精修，供 GPT 按模块逐项落地：
1. **「检查更新」补齐旋转微动画，并将反馈固定在顶栏右侧胶囊**（不再塞进滚动内容流顶部，页面滚到任何位置都能直接看见，无新版时 4 秒自动收起）；
2. **「添加账号 → 浏览器登录」禁止自动拉起默认浏览器**：拿到链接后**自动复制到剪贴板**，并在表单中展示**不可编辑的只读链接输入框（点一下即复制）+ 右侧「打开」按钮**；
3. **「添加账号 → 提供方」替换为带 `<ProviderMark />` 图标的暗色自定义下拉选择器**（收起态与展开列表每一项均带对应品牌图标）。

## 1. 「检查更新」旋转微动画与固定顶栏胶囊反馈（免滚动可见）

### 1.1 现状根因
1. [TopBar.tsx](../../src/renderer/components/TopBar.tsx) 仅在 `status` 为 `'available' | 'downloading' | 'downloaded'` 时渲染 `.titlebar-update`，从「设置 → 检查更新」或「系统托盘 → 检查更新」触发时，顶栏没有任何检查中的旋转微动画。
2. [AccountsDialog.tsx](../../src/renderer/components/AccountsDialog.tsx) 页脚按钮在 `checking` / `downloading` 状态下只有纯文字（`检查中…` / `下载中…`），缺少旋转图标反馈。
3. [main.tsx](../../src/renderer/main.tsx) 将手动检查结果 `.update-notice` 渲染在 `<main className="app-scroll"><div className="usage-container">` 顶部，当用户已向下滚动浏览明细表时，检查结果出现在视口上方，必须手动滚回顶部才能看到。

### 1.2 实现要求

#### 1.2.1 区分手动检查与后台静默检查（`src/shared/updateTypes.ts`、`src/main/updater.ts`）
- 在 `UpdateState` 中新增可选字段 `manual?: boolean`。
- 在 [updater.ts](../../src/main/updater.ts) 的 `checkForUpdates(silent = false)` 中：
  - 记录当前轮检查是否为手动触发（`manual = !silent`；若已有后台 `silent` 检查在进行中，而用户又从设置菜单/弹窗/托盘触发了 `checkForUpdates(false)`，立即升级为 `manual = true` 并广播 `{ ...state, manual: true }`）。
  - 在 `checking` 以及该轮手动检查落定的 `up-to-date`、`idle`（如开发模式提示或 404 无版本）、`error` 状态中保留 `manual: true`；而后台定时静默检查（启动后 `10s` 与每 `4h`）保持 `manual` 为 `false`/`undefined`，无新版时继续对用户完全透明。

#### 1.2.2 自动收起反馈与状态同步（`src/renderer/hooks/useUpdates.ts`、`src/renderer/updatePresentation.ts`）
- 在 `useUpdates` 中：
  - 统一根据 `state` 变化识别手动检查结果（涵盖渲染进程点击 `updates.run()` 以及主进程托盘菜单「检查更新」推送的 `manual: true` 状态）：当手动检查进入终态 `up-to-date`、`idle`（带提示消息）或 `error`，或手动下载/安装进入 `error` 时，生成 `feedback: UpdateFeedback`。
  - 为 `feedback` 增加 **`4000 ms` 自动收起定时器**（组件卸载、开始新一轮 `checking`/`downloading` 或手动点击关闭时清理旧定时器），实现「无新版时在顶栏胶囊显示 4 秒后自动收起」。

#### 1.2.3 固定顶栏胶囊与弹窗页脚微动画（`src/renderer/main.tsx`、`src/renderer/components/TopBar.tsx`、`src/renderer/components/AccountsDialog.tsx`、`src/renderer/styles/globals.css`）
1. **移除滚动区顶部横幅（`src/renderer/main.tsx`）**：
   - 删除 `<div className="usage-container">` 内原有的 `.update-notice` 节点（清理 `globals.css` 中废弃的 `.update-notice` 样式）。
   - 向 `<TopBar />` 传入 `accountsOpen={modal?.kind === 'accounts'}`，当「账号管理」弹窗正处于打开状态时，结果已在弹窗固定页脚实时呈现，顶栏无需重复叠出临时结果胶囊。
2. **顶栏右侧固定胶囊（`src/renderer/components/TopBar.tsx`）**：
   - 在固定不随页面滚动的 `<header className="titlebar">` 右侧 `.titlebar-tools` 内（「刷新」按钮左侧）按优先级展示：
     - **`status === 'checking' && state.manual`**：渲染禁用态胶囊 `.action-button.titlebar-update`，左侧带 `<LoaderCircle size={13} className="motion-safe:animate-spin" aria-hidden="true" />`，文案为 `正在检查…`；
     - **`status === 'downloading'`**：渲染禁用态胶囊 `.action-button.titlebar-update`，左侧带 `<LoaderCircle size={13} className="motion-safe:animate-spin" aria-hidden="true" />`，文案为 `下载中 {percent}%`；
     - **`status === 'available'` / `'downloaded'`**：保持可点击胶囊（`新版本 v{latestVersion}` / `重启更新` / `查看新版`）；
     - **临时结果胶囊（`updates.feedback && !accountsOpen`）**：渲染紧凑胶囊容器 `.titlebar-update-feedback`（当 `updates.feedback.error` 为真时附带错误文字色），显示 `updates.feedback.text`（如 `已是最新版本`、`暂未检测到已发布的新版本`）及右侧小号关闭按钮 `<button type="button" aria-label="关闭更新提示" ...><X size={12} /></button>`，4 秒无操作自动收起。
   - `#settings-panel` 菜单内的更新项在 `checking` / `downloading` 时同样附带旋转小图标或保持清晰状态文案。
3. **「账号管理」页脚按钮微动画（`src/renderer/components/AccountsDialog.tsx`）**：
   - 在 `<footer className="dialog-footer accounts-dialog-footer">` 右侧操作按钮内，当 `updates.state?.status === 'checking' || updates.state?.status === 'downloading'` 时，在按钮文字前渲染 `<LoaderCircle size={13} className="motion-safe:animate-spin" aria-hidden="true" />`（按钮文案对应 `检查中…` / `下载中…`）。

## 2. 「浏览器登录」免自动弹窗 + 自动复制 + 点击只读输入框复制 + 右侧「打开」按钮

### 2.1 主进程改动（彻底禁止自动拉起默认浏览器 + 剪贴板 IPC）
1. **`src/main/accounts/loginManager.ts`**：
   - **删除 `showAuth` 中的自动打开浏览器调用**：`Antigravity`、`Codex`、`Claude Code` 三家在拿到授权 URL 后**一律不自动调用 `options.openExternal`**，只将经过白名单校验的 `safeUrl` 写入 `AccountLoginState.authorizationUrl` 推送给前端。
   - **清理 ANSI 转义序列**：按行扫描 `stdout` / `stderr` 提取 `https://...` 前，先剥离 CSI 控制序列（如 `raw.replace(/\x1b\[[0-9;?]*[A-Za-z]/g, '')`），防止 TUI 颜色或光标控制符混入链接末尾。
   - **补齐 Claude 授权域名**：将 `providers.claude` 允许的主机名扩展为 `['claude.ai', 'claude.com', 'platform.claude.com', 'console.anthropic.com']`。
2. **`src/main/accounts/externalUrl.ts`**：
   - `allowedHosts` 同步补入 `'claude.com'` 与 `'platform.claude.com'`。
3. **`src/main/accounts/loginProcess.ts`**：
   - 在 `claudeLoginEnvironment(root)` 中显式注入 `BROWSER: '__USAGE_DASHBOARD_NO_BROWSER__'`：
     - Windows 实机验证确认：`claude.exe auth login --claudeai` 在未设置 `BROWSER` 时会调用 `rundll32 url,OpenURL` 强行拉起默认浏览器；设置 `BROWSER: '__USAGE_DASHBOARD_NO_BROWSER__'` 后会跳过 `rundll32`，并在 `stdout` 单行完整打印 `https://claude.ai/oauth/authorize?z-...` 短链，同时保持本地回调监听正常等待完成。
4. **新增主进程剪贴板写入 IPC（`src/shared/ipc.ts`、`src/preload/index.ts`、`src/main/ipc.ts`）**：
   - 原因：CLI 子进程返回 `authorizationUrl` 发生在用户点击「浏览器登录」约 `0.2s ~ 2s` 之后的异步推送回调中，直接用渲染进程 `navigator.clipboard.writeText` 可能因瞬态用户激活过期或焦点切换而失败。
   - 新增通道 `copyText: 'usage:copy-text'` 与 `UsageApi.copyText(text: string): Promise<void>`；
   - 在 `src/main/ipc.ts` 中校验 `ownWindow(event)` 且 `typeof text === 'string' && text.length > 0 && text.length <= 8192` 后，调用 Electron 主进程 `clipboard.writeText(text)`。

### 2.2 前端登录链接交互（`src/renderer/components/AccountsDialog.tsx`、`src/renderer/styles/globals.css`）
1. **生成链接瞬间自动复制**：
   - 在 `AddAccountForm` 中使用 `autoCopiedKeyRef = useRef<string | null>(null)` 记录 `${state.flowId}:${state.authorizationUrl}`；
   - 当 `(waitingBrowser || waitingCode) && state.flowId && state.authorizationUrl` 首次就绪时，自动调用 `window.usageApi.copyText(state.authorizationUrl)` 将链接写入系统剪贴板，并置 `copied = true`（`2000 ms` 后恢复常态提示，组件卸载或切换流程时清理定时器；若拷贝异常则静默降级不阻断登录）。
2. **不可编辑链接输入框（单击即复制）+ 右侧「打开」按钮**：
   - 当 `(waitingBrowser || waitingCode) && state.authorizationUrl` 存在时，渲染「授权链接」行：
     - 顶部标签行：左侧 `授权链接`，右侧轻提示文案（`copied ? '已复制链接' : '点击输入框复制'`）；
     - 控件行 `.login-url-row`（水平 `flex` 排列，`gap: 8px`）：
       - **左侧只读输入框**：
         ```tsx
         <input
           type="text"
           readOnly
           value={state.authorizationUrl}
           aria-label="授权链接，点击复制"
           title="点击复制授权链接"
           className="price-field login-url-input"
           onClick={() => void copyAuthorization()}
           onKeyDown={(event) => {
             if (event.key === 'Enter' || event.key === ' ') {
               event.preventDefault()
               void copyAuthorization()
             }
           }}
         />
         ```
         样式要求：`flex: 1; min-width: 0; cursor: pointer; text-overflow: ellipsis; user-select: none;`（不可编辑，鼠标移上去为手型指针，点一下即复制整条链接并触发 `copied = true` 视觉反馈）。
       - **右侧「打开」按钮**：
         ```tsx
         <button
           type="button"
           className="action-button"
           disabled={cancelling || verifying}
           onClick={() => void openAuthorization()}
         >
           打开
         </button>
         ```
         点击调用 `window.usageApi.openExternalUrl(state.authorizationUrl)` 在系统默认浏览器打开。
   - 底部操作栏移除旧的 `打开授权页面` / `重新打开链接` 按钮，仅保留 `取消` 与（当 `waitingCode` 时的）`完成登录` 按钮，层级清晰不重复。
   - 状态引导文案同步更新为：
     - `waitingBrowser`：`链接已自动复制，可粘贴到任意浏览器或点击右侧「打开」完成授权`（或简洁表述 `请在浏览器打开上方链接完成授权`）；
     - `waitingCode`：`完成浏览器授权后，在下方粘贴授权码`。

## 3. 「添加账号 → 提供方」带品牌图标的暗色自定义下拉组件

### 3.1 问题原因
浏览器原生 `<select>` / `<option>` 在 Windows 上使用系统级蓝底白字菜单（见实机截图），不支持渲染自定义 SVG/PNG 品牌图标（`<ProviderMark />`），视觉上也与暗黑衬线风格割裂。

### 3.2 实现要求（`src/renderer/components/AccountsDialog.tsx`、`src/renderer/styles/globals.css`）
- 在 `AccountsDialog.tsx` 中实现轻量无依赖的自定义下拉选择器 `ProviderSelect`，替换 `AddAccountForm` 中的原生 `<select>`：
  1. **收起态触发按钮**（`.price-field.provider-select-trigger`）：
     - 保持 `height: 30px`、`#000000` 背景、`1px solid #ffffff23` 边框与 `5px` 圆角，与右侧「显示名」输入框完全对齐；
     - 左侧展示 `<ProviderMark provider={value} className="size-4 shrink-0" />` + 提供方名称 `{providerInfo[value].label}`，右侧展示 `<ChevronDown size={14} aria-hidden="true" />`；
     - 具备 `type="button"`、`aria-haspopup="listbox"`、`aria-expanded={open}`，表单初次展开时默认获得焦点（`autoFocus`），在 `disabled`（`busy || active || cancelling`）时禁用并自动收起浮层。
  2. **展开态下拉浮层**（`.provider-select-menu`，采用原生 `popover="auto"` 以突破 `<dialog>` 裁剪区置于顶层，复用 `#111111` 面板底色、`1px solid #242424` 边框与阴影，宽度与触发按钮等宽 `trigger.getBoundingClientRect().width`）：
     - 渲染全部 4 个提供方选项（`<button type="button" role="option" aria-selected={entry === value}>`）：
       - 左侧 `<ProviderMark provider={entry} className="size-4 shrink-0" />`
       - 中间提供方名称 `{providerInfo[entry].label}`
       - 右侧选中态对勾 `{entry === value && <Check size={14} aria-hidden="true" />}`
     - **键盘无障碍与防误关弹窗**：
       - 支持 `ArrowDown`、`ArrowUp`、`Home`、`End` 循环移动高亮焦点，`Enter` / `Space` 选中并关闭浮层回焦触发按钮；
       - 在下拉浮层打开时按 `Escape`，必须 `event.preventDefault(); event.stopPropagation()` 仅关闭下拉浮层并回焦触发按钮，**绝不能连带关闭外层的「账号管理」`<dialog>`**；
       - 窗口尺寸变化或弹窗滚动时同步更新浮层定位（复用 `TopBar` 的 `position-area` / 坐标计算模式）。

1. `tests/accountLogin.test.ts`：
   - 验证 `Antigravity`、`Codex`、`Claude Code` 三家登录流程在收到授权链接时**均不再自动调用 `openExternal`**；
