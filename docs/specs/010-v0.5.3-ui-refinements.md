## 2. 托盘小面板「指哪显哪」悬浮微提示重构

涉及文件：[src/renderer/trayPresentation.ts](../../src/renderer/trayPresentation.ts)、[src/renderer/components/TrayPanel.tsx](../../src/renderer/components/TrayPanel.tsx)、[src/renderer/styles/tray-panel.css](../../src/renderer/styles/tray-panel.css)。

### 2.1 现状问题根因
1. `<li class="tray-quota">` 整行绑定了 `onPointerEnter` / `onFocus` 且带 `tabIndex={0}`，导致鼠标移入窗口名、百分比、重置时间乃至右侧空白槽都会误弹额度条明细，点击某行还会因焦点停留造成提示框粘连残留；同时各子元素带有浏览器原生 `title`，出现系统白框与自绘深色提示框双重打架。
2. `trayQuotaTooltip` 在 `!reading.resetsAt` 时直接返回 `null`，导致满血 `100%` 未开始计时的额度条悬浮无任何反馈；此外 `.tray-tip` 位于 `.tray-scroll` 内部且 `.tray-track` 仅 `6px` 高，存在边缘 `overflow: auto` 裁切与细条轻微移位脱靶问题。

### 2.2 移除整行监听与原生 `title`
1. 移除 `<li class="tray-quota">` 上的 `tabIndex`、`onPointerEnter`、`onPointerLeave`、`onFocus`、`onBlur`（保留语义化无障碍阅读文本，不再让整行因鼠标点击捕获焦点弹框）。
2. 移除托盘账号标题行与额度行内所有元素的浏览器原生 `title` 属性（邮箱、重置券徽章、窗口简称、百分比、重置时间），统一使用同一套自绘深色微提示 `.tray-tip`。
3. 无内容的空占位槽（如无重置时间时的 `<span class="tray-reset" aria-hidden="true" />`）及列间空白区域不绑定任何悬浮事件。

### 2.3 六类信息单元的独立触发规则与展示文案

鼠标悬浮到具体哪个信息元素上，仅展示该元素对应的明细（`event.pointerType === 'touch'` 忽略）：

1. **账号邮箱（`.tray-account-heading .tray-ellipsis`）**
   - **触发条件**：仅当元素实际发生横向省略截断（`element.scrollWidth > element.clientWidth`）时触发；完整显示时不弹。
   - **文案**：完整邮箱字符串（`account.displayName`）。

2. **Codex 重置券徽章（`.tray-credit`，`credits > 0`）**
   - **触发条件**：悬浮于 `.tray-credit` 徽章上。
   - **文案**：`${credits} 张重置券 · 可在主面板使用`。

3. **左侧窗口简称（`.tray-quota-label`）**
   - **触发条件**：当显示简称与原始全称不同（`trayWindowLabel(window) !== window.label`，如 `Gemini 5h`、`Claude&GPT 周`）**或**元素发生横向省略截断（`element.scrollWidth > element.clientWidth`）时触发；未缩写且未截断（如 `5-Hour`、`Weekly`）时不弹。
   - **文案**：完整窗口名 `window.label`（如 `Claude & GPT (shared) · Weekly`）。

4. **中间额度条（`.tray-track` 热区）**
   - **热区扩展**：视觉轨道保持 `6px` 高居中绘制（`::before` / `::after` 垂直居中，匀速刻度线 `.tray-tick` 保持 `12px` 高居中跨越轨道），但 `.tray-track` 容器自身撑满整行高度（`align-self: stretch; min-block-size: 19px`），消除 `6px` 极细热区脱靶问题。
   - **触发条件**：悬浮于 `.tray-track` 上**始终**展示额度进度明细（含无 `resetsAt` 的满血窗口）。
   - **文案（`trayQuotaTooltip(reading, now, tick)`）**：
     - **有有效 `resetsAt`**（`at = Date.parse(reading.resetsAt)` 有限）：
       - 当 `at <= now`：`即将重置`（若 `reading.stale` 追加 ` · 缓存`）；
       - 当 `at > now`：若有 `tick`（`expectedRemainingPercent !== null && expectedRemainingPercent !== undefined`），依次拼接 `匀速应剩 ${Math.round(tick)}%` 与 `还需 ${remainingText(at - now)}`（无 `tick` 时仅 `还需 ${remainingText(at - now)}`）；若 `reading.stale` 追加 ` · 缓存`（例：`匀速应剩 68% · 还需 1 小时 34 分`）。
     - **无有效 `resetsAt`**（如满血未使用）：
       - 拼接 `剩余 ${formatLimitPercent(reading.remainingPercent)} · 尚未开始计时`（例：`剩余 100% · 尚未开始计时`；若 `reading.stale` 追加 ` · 缓存`）。

5. **右侧剩余百分比（`.tray-percent`）**
   - **触发条件**：悬浮于百分比数字上。
   - **文案（`trayPercentTooltip(reading)`）**：`剩余 ${formatLimitPercent(reading.remainingPercent)}`（最多保留 1 位小数，如 `剩余 91.4%`、`剩余 100%`），若 `reading.stale` 追加 ` · 缓存`。

6. **最右侧重置时间（`<time class="tray-reset">`，非空时）**
   - **触发条件**：**仅当当前显示的短文本属于 `周XHH:MM` 分支**（即本地日历距离 `0 < days < 7`）时触发悬浮提示；当天 `HH:MM`（如 `14:01`）、`即将重置` 及 7 天及以上日期（如 `1/11 17:23`）**均不弹提示**。
   - **文案（`trayResetTooltip(resetsAt, now)`）**：
     - 返回两位补零的本地日期+星期时刻：**`MM月DD日 周XHH:MM`**（`pad(month)`、`pad(day)`、`pad(hour)`、`pad(minute)`），例如 `11月28日 周六15:34`、`01月03日 周五17:23`。

### 2.4 面板级浮层定位、防边缘裁切与清理
1. **脱离 `.tray-scroll` 渲染**：
   - `.tray-panel` 设为 `position: relative`；将唯一的 `<span ref={tipRef} className="tray-tip" role="tooltip">` 渲染在 `<section className="tray-panel">` 顶层（位于 `.tray-scroll` 之外），避免被滚动容器 `overflow: auto` 裁切。
2. **就近贴合目标元素并自动防溢出**：
   - 触发时记录目标元素的 `target.getBoundingClientRect()` 与 `.tray-panel` 的 `panel.getBoundingClientRect()`；
   - **垂直定位**：默认显示在目标元素正上方（间距 `4px`）；当 `targetRect.top - panelRect.top < 32`（靠近面板顶部）时自动翻转至目标元素正下方（间距 `4px`）；
   - **水平定位**：在 `useLayoutEffect` 中结合 `tipRef.current.offsetWidth`，以目标元素水平中心 `(targetRect.left + targetRect.right) / 2 - panelRect.left` 为基准居中对齐，并夹紧在 `[8, panelRect.width - tipWidth - 8]` 安全区内（`max-inline-size: calc(100% - 16px)`），确保悬浮最右侧 `周六15:34` 或中间进度条时，提示框都精准出现在所指元素正上方/正下方且不超出面板右缘。
3. **即时收起**：
   - 目标元素 `onPointerLeave`、`.tray-scroll` 触发 `onScroll`、整个 `.tray-panel` `onPointerLeave` 或窗口触发 `blur` 时，立即清空 `tooltip` 状态，杜绝滚动或移出面板后悬浮框残留。

### 4.2 主进程官方标准预设价格聚合器（[src/main/usage/pricePresets.ts](../../src/main/usage/pricePresets.ts)）
由于渲染进程启用严格 CSP `default-src 'self'`，预设列表统一由主进程组装，经 IPC 通道 `usage:get-price-presets`（`window.usageApi.getPricePresets(): Promise<PricePreset[]>`）暴露给主窗口。

1. **`PricePreset` 结构（所有单价单位均为「美元 / 百万 token」，经 `Number(value.toPrecision(10))` 消除浮点尾差）**：
   ```ts
   export type PricePresetSource = 'models.dev' | 'litellm'
   export interface PricePreset {
     id: string                              // 唯一键，如 "models.dev:moonshotai/kimi-k3"
     modelId: string                         // 原厂标准模型 ID，如 "moonshotai/kimi-k3"、"anthropic/claude-opus-5-5"
     label: string                           // 可读模型名称，如 "Kimi K3"（缺失时回退 modelId）
     providerLabel: string                   // 统一原厂展示名，如 "Moonshot AI"、"Anthropic"、"Alibaba"、"LiteLLM"
     source: PricePresetSource
     aliases?: string[]                      // 可选检索别名（当目录键名与 canonical_model_id slug 不同，如 "deepseek-flash"）
     inputCostPerMillionTokens: number
     outputCostPerMillionTokens: number
     cacheReadCostPerMillionTokens?: number  // 仅当源数据显式给出缓存读取价时提供，缺失留 undefined
     cacheWriteCostPerMillionTokens?: number // 仅当源数据显式给出缓存创建价时提供，缺失留 undefined
   }
   ```
2. **纯官方标准库与「每模型唯一 1 套预设」规则**（不混入本机 `opencode.jsonc` 自定义配置）：
   - **第 1 层 — `models.dev` 原厂唯一目录（`source: 'models.dev'`）**：

### 8.2 模型客观热门度：`release_date` 新鲜度 × 全网 `adoptionCount` 接入广度 + `modalities` 过滤/降权（[pricePresets.ts](../../src/main/usage/pricePresets.ts)）
1. **全库渠道接入数 `adoption` 与缓存升级（`CATALOG_VERSION = 4`）**：
   - 在 `fetchModelsDev` 中对原始响应文本使用安全白名单投影（仅解码顶层各 Provider 下各模型的 `canonical_model_id: "string"`，严禁解码 `apiKey` / `baseURL` / `headers` / `options` / `name`），统计每个规范化小写 `canonical_model_id` 被全库多少个**不同顶层 Provider** 收录，生成 `adoption: Record<string, number>`；
   - `presetProvider` 投影 schema 扩展为 `{ canonical_model_id: "string", release_date: "string", modalities: { fields: { output: { items: "string" } } }, cost: presetCost }`；
   - `models-dev-cache.json` 升级 `version: 4`，结构为 `{ version: 4, source, fetchedAt, adoption, catalog }`（旧版 `version < 4` 缓存自动失效重拉）。
2. **非对话模型剔除与多模态输出降权**：
   - **直接剔除**：若 `modalities.output` 为非空数组且不含 `"text"`（如纯生图 `["image"]`、纯 TTS `["audio"]`、纯视频 `["video"]`），或 `cost.output === 0` 且键名含 `embed` / `rerank`（纯向量/重排），直接跳过不收录；
   - **多模态生成降权**：若 `modalities.output` 同时含 `"text"` 与 `"image"` / `"audio"` / `"video"`（如 `openai/chatgpt-image-latest`、`google/gemini-3.1-flash-image`、`openai/gpt-realtime-2.1`），保留条目供精确匹配/搜索，但热门度乘以 `0.05`，防止霸占默认浏览首屏。
3. **热门度公式（相对目录最新日期计算，离线不随系统时钟漂移）**：
   - 取当前 `catalog` 内所有有效 `YYYY-MM-DD` `release_date` 的最大时间戳 `maxReleaseMs` 为基准；条目有合法 `release_date` 时 `daysOld = Math.max(0, (maxReleaseMs - releaseMs) / 86_400_000)`，缺失时按冷门旧模型取 `daysOld = 730`；
   - `popularity = Number((((adoption[baseCanonicalId] ?? 1) + 8) * Math.exp(-daysOld / 150) * (isMultimodalOutput ? 0.05 : 1)).toPrecision(6))`。
4. **每模型唯一默认代表项 `primary` 标记**：
   - 按 `isCanonicalOwner` 优先 → `providerRank` 升序 → `popularity` 降序扫描：每个 `canonicalId` 仅将第 1 个命中的原厂条目（`isCanonicalOwner === true`，或 Tier A 无收录时命中 `domesticOwners` 的 `-cn` 国内独有原厂条目）标记为 `primary: true`，其余渠道条目 `primary: false`；
   - `loadPricePresets` 最终返回数组按 `popularity` 降序 → `isCanonicalOwner` 优先 → `providerRank` 升序 → `modelId` 字典序排列。

2. **`filterPricePresets(presets, query, rowModel = '', limit = 80)` 三态编排（无本机历史渠道提权）**：

## 9. 四次实机验收修订项：首屏各厂正代主力轮询、衍生子变体压制与容错相关性搜索（交由 GPT 执行）

保持**目标 2**（填 `provider/model` 时的多渠道匹配与顺位编排）不变，针对**目标 1**（空填默认态中开源模型因全库托管商多而跨厂刷票、以及 `-flashx` / `-highspeed` 子变体蹭母款 `adoption` 反超正代登顶的问题）与**搜索体验**，升级如下（无需升级缓存版本号，继续复用 `CATALOG_VERSION = 4`）：

### 9.1 厂内评分校正与衍生子变体降权（[pricePresets.ts](../../src/main/usage/pricePresets.ts)）
1. **消除开源 vs 闭源跨厂刷票失真 & 子变体蹭热度**：
   - 识别衍生/垂类变体后缀：`DERIVED_VARIANT = /(?:^|[-_./])(?:highspeed|flashx|healthcare|legal|customtools|contributor|vision-exp|free)(?:$|[-_./])/i`；
   - 识别轻量档后缀：`LIGHT_TIER = /(?:^|[-_./])(?:flash|lite|mini|nano|haiku)(?:$|[-_./])/i`；
   - **子变体独立计分**：在同 Provider 内因单价不同而从主 `canonicalId` 拆分出的子变体（即 `variantId = `${candidate.canonicalId}:${candidate.key}``，如 `zai/glm-5.3-flashx`、`moonshotai/kimi-k3.1-pro-highspeed`），**不得继承母款的 `adoption[canonicalId]`**（其 `effectiveAdoption` 固定按 `1` 计），且强制标记为衍生变体（`derived = true`）；普通主条目若 `key` 或 `canonicalSlug` 命中 `DERIVED_VARIANT`（如 `gpt-6.2-sol-healthcare`、`glm-5.3-flashx-legal`），同样标记 `derived = true`；
   - **对数压缩厂内热度公式**（`adoption` 经 `Math.log2` 压缩后仅用于同厂内区分主力与冷门，180 天时间衰减保证同代旗舰压过晚十几天发布的轻量款）：
     - `tierWeight = derived ? 0.25 : LIGHT_TIER.test(key) ? 0.85 : 1`
     - `popularity = Number((Math.log2(effectiveAdoption + 2) * Math.exp(-daysOld / 180) * tierWeight * (multimodal ? 0.05 : 1)).toPrecision(6))`
     （例如智谱内部正代 `zai/glm-5.3` 自然排在 `zai/glm-5.3-flash` 前面，而衍生变体 `zai/glm-5.3-flashx` 排在二者之后；OpenAI 内部 `gpt-6.2-sol` 远高于仅 2 家接入的 `gpt-6.2-sol-healthcare`）。
   - 可在 `PricePreset`（[types.ts](../../src/shared/types.ts)）上新增可选布尔字段 `derived?: boolean`（默认 `false`），供前端首屏轮询与搜索同分排序识别正代主力模型。

### 9.2 目标 1 默认空行浏览：主流原厂前两轮正代主力轮询 + 厂内分块排列（[PriceOverridesDialog.tsx](../../src/renderer/components/PriceOverridesDialog.tsx)）
1. **当 `query` 为空且 `rowModel` 为空时（`defaultBrowsePresets`）**：
   - 先筛出 `preset.primary !== false` 的唯一原厂代表项，按 `providerRank`（未设时取 `999`）分组；
   - 每个厂商组内部按：`Number(Boolean(a.derived)) - Number(Boolean(b.derived)) || presetPopularity(b) - presetPopularity(a) || a.modelId.localeCompare(b.modelId)` 排序（同厂最新正代旗舰排第 1）；
   - **首屏前两轮轮询精选（Spotlight Round-Robin）**：对头部主流原厂组（`providerRank < 10`，即 `OpenAI`、`Anthropic`、`Google`、`DeepSeek`、`Alibaba`、`Moonshot AI`、`Zhipu AI`、`MiniMax`、`xAI`、`Mistral`，若测试夹具未设 `providerRank` 或均 `< 10` 则按实际分组顺序）：
     - **第 1 轮**：按厂商顺位依次取出每家第 1 款非衍生（`!preset.derived`）代表模型；
     - **第 2 轮**：按厂商顺位依次取出每家第 2 款非衍生（`!preset.derived`）代表模型；
   - **后续列表**：将其余尚未取出的 `primary` 代表模型按 `providerRank` 升序 → 厂内排序依次追加在后面，最后 `.slice(0, limit)`。
   - **目标 2 未命中尾部（`query` 为空、`rowModel` 非空时的 `score === 0` 兜底段）**：同样复用该 `defaultBrowsePresets` 顺序垫底，保持体验一致。

### 9.3 搜索升级：忽略分隔符容错匹配 + 命中相关性分级排序（[PriceOverridesDialog.tsx](../../src/renderer/components/PriceOverridesDialog.tsx)）
1. **去分隔符归一化容错匹配（支持 `opus 5.5`、`opus55`、`glm53`、`gpt6.2` 命中 `claude-opus-5-5`、`zai/glm-5.3` 等）**：
   - 定义 `compact = (value: string) => value.replace(/[-_./\s]+/g, '')`；
   - 对每个预设构造原始检索串 `haystack`（小写空格拼接 `modelId`、`providerId`、`providerLabel`、`canonicalId`、`aliases`）以及紧凑检索串 `compactHaystack`（对上述各字段分别 `compact` 后拼接）；
   - 每个搜索分词 `token` 满足 `haystack.includes(token)` **或**（`compact(token).length >= 2 && compactHaystack.includes(compact(token))`）即视为命中。
2. **搜索结果相关性分级打分 `searchRelevance(preset, normalizedQuery, tokens)`**：
   - 取 `bare = lastSegment(preset.modelId.toLowerCase())`、`full = preset.modelId.toLowerCase()`：
     - `4`（精确命中）：`full === normalizedQuery || bare === normalizedQuery`（例如搜 `glm-5.3` 时，`zai/glm-5.3` 得 `4` 分，严格排在 `zai/glm-5.3-flash` 和 `zai/glm-5.3-flashx` 之前）；
     - `3`（前缀 / 边界命中）：`bare.startsWith(normalizedQuery) || full.startsWith(normalizedQuery)`，或所有 `tokens` 均命中 `full` 中词段开头（`(^|[-_./])` 边界）；
     - `2`（原始子串命中）：所有 `tokens` 均直接命中原始 `haystack.includes(token)`；
     - `1`（容错模糊命中）：依赖去分隔符 `compactHaystack` 命中的条目（如搜 `opus 5.5` 或 `opus55` 命中 `claude-opus-5-5`）。
   - **搜索排序规则**：
     - 若 `rowModel` 非空：先按 `matchScore(preset, rowModel)` 降序，再按 `searchRelevance` 降序 → `Number(Boolean(a.derived)) - Number(Boolean(b.derived))` → `popularity` 降序 → `providerRank` 升序 → `modelId` 升序；
     - 若 `rowModel` 为空：按 `Number(b.primary !== false) - Number(a.primary !== false)`（原厂代表优先） → `searchRelevance` 降序 → `Number(Boolean(a.derived)) - Number(Boolean(b.derived))`（正代优先于 `-flashx` / `-highspeed`） → `popularity` 降序 → `providerRank` 升序 → `modelId` 升序。

## 13. 兼容 OpenCode `opencode.db`（`models-dev:v3:catalog`）只读目录计价（`opencodePricing`）

### 13.1 问题背景
- 新版 OpenCode CLI 已不再更新旧版文件缓存 `~/.cache/opencode/models.json`，而是将最新模型价格目录写入 SQLite 数据库 `opencode.db` 的 `kv` 表（`key = 'models-dev:v3:catalog'`），导致仅存在于新版目录中的模型（如 `alibaba-cn/deepseek-v4.1-flash-1017`）在 UsageBoard 中因查不到单价被标为 `未定价`。

### 13.2 只读读取、WAL 指纹与脱敏投影规范（[opencodePricing.ts](../../src/main/usage/opencodePricing.ts)）
1. **数据库候选路径（`opencodeDbPaths`）**：
   - 对齐 [discovery.ts](../../src/main/accounts/discovery.ts) 中 `opencode` 数据目录规则，收集去重后的 `opencode.db` 路径：`OPENCODE_DATA_DIR`（支持逗号分隔）→ 否则 `XDG_DATA_HOME/opencode/opencode.db`（未设则为 `~/.local/share/opencode/opencode.db`）以及 Windows 下 `%LOCALAPPDATA%\opencode\opencode.db`。
2. **包含 `-wal` 的热加载缓存指纹**：
   - SQLite 在 WAL 模式下新事务可能先写入 `opencode.db-wal` 而未立即更新主库 `mtimeMs`；因此对每个候选 `dbPath`，缓存签名必须同时纳入 `fingerprint(dbPath)` 与 `fingerprint(`${dbPath}-wal`)`。
3. **只读 SQLite 读取与白名单脱敏投影**：
   - 使用 Node 内置 `DatabaseSync(dbPath, { readOnly: true })`，执行 `PRAGMA busy_timeout = 100`，查询 `SELECT value FROM kv WHERE key = 'models-dev:v3:catalog' LIMIT 1` 并在 `finally` 中关闭连接（表不存在、库繁忙或损坏均静默忽略，绝不阻塞用量扫描）；
   - 先对 `row.value` 用 `project(..., { fields: { body: "string" } }, false)` 提取 `body` JSON 字符串，再对 `body` 用 `project(..., v3ProvidersShape, false)` 做严格白名单投影——**仅解码模型 `id` 与 `cost.text` 价格字段，严禁解码 `api`、`base_url`、`env`、`options`、`headers` 等无关或敏感子树**。
4. **v3 `cost.text` 到 `ModelRate` 的映射规则**：
   - **基础单价**：读取 `cost.text.input.price` 与 `cost.text.output.price`（非负有限数，除以 `1e6` 转为每 token 美元；任一缺失则跳过该模型）；
   - **缓存单价兼容全量结构**：
     - `cacheRead`：优先 `input.cache.read ?? input.cache.explicit?.read`（缺失回退 `input.price`），除以 `1e6`；
     - `cacheWrite` 与 `cacheWrite1h`：检查 `w = input.cache.write ?? input.cache.explicit?.write`——若 `w` 为非负数字，则 `cacheWrite = cacheWrite1h = w / 1e6`；若 `w` 为对象（兼容 `{ "5m", "1h" }` 与 `{ "30m", "12h" }`），则 `cacheWrite = (w["5m"] ?? w["30m"] ?? input.price) / 1e6`，`cacheWrite1h = (w["1h"] ?? w["12h"] ?? (w["5m"] ?? w["30m"] ?? input.price)) / 1e6`；若均未提供则回退 `input.price / 1e6`；
   - **上下文阶梯价（`tiers`）**：收集 `cost.text.input.overrides` 与 `cost.text.output.overrides` 中 `when.context.gt` 为正数的条目，按相同 `threshold = gt` 配对合并（某侧未覆盖时继承基础输入/输出/缓存单价），按 `threshold` 降序写入 `ModelRate.tiers`（本版本暂不处理 `multipliers` 与 `web_search`）。
5. **目录合并优先级**：
   - `catalogRates` 先合并旧版 `models.json`，再合并 `opencode.db` 的 `models-dev:v3:catalog`（同名 `<provider>/<model>` 以新版 `v3` 目录覆盖旧文件缓存）；整体计价优先级保持 `UsageBoard priceOverrides > OpenCode 用户配置单价 > OpenCode 目录缓存（v3 db > models.json） > LiteLLM`。

## 16. Antigravity CLI 识别加固、邮箱胶囊内常驻异常图标与悬浮引导

### 16.1 问题背景
1. **未安装 `agy` CLI 用户的续期真相与两处代码隐患**：
   - Antigravity 桌面端写入 Windows 系统凭据 `gemini:antigravity`（以及应用内 `agy acp --login` 保存的 `antigravity-oauth-token`）的 `access_token` 有效期均为 **1 小时**，且凭据内不含 OAuth `client_secret`；一旦桌面端未在后台刷新或账号为非当前备用账号，1 小时后必须调用本机 `agy` CLI 续期（Dashboard 内置的 Antigravity 登录同样依赖 `agy` CLI，不能错误引导未装 CLI 的用户去点内置登录）；
   - [cli.ts](../../src/main/limits/probes/cli.ts) `resolveAgyCli` 在 Windows 的 `PATH` 搜索名单里包含了 `'antigravity.exe'`，若用户将桌面端目录加入 `PATH`，会把 Electron GUI 主程序误判为 CLI 拉起执行 `acp`，导致卡死并报笼统的 `刷新失败`；
   - [loginManager.ts](../../src/main/accounts/loginManager.ts) 在缺少 CLI 时提示 `请先安装 Antigravity 后再登录`（漏写 `CLI`），令已装桌面端的用户困惑。
2. **底部黄色警告栏难发现、点击「重试」无反馈且缺乏恢复引导**：
   - [LimitsView.tsx](../../src/renderer/components/LimitsView.tsx) 将 `.limit-warning-alert` 渲染在所有提供方卡片最底部，用户需滚到底才能看见，且无历史缓存的异常账号会直接从顶部邮箱胶囊栏消失；点击「重试」后若依旧失败，界面没有任何状态变化或下一步操作入口。

### 16.2 CLI 识别与登录提示修正（[cli.ts](../../src/main/limits/probes/cli.ts) & [loginManager.ts](../../src/main/accounts/loginManager.ts)）
1. **`resolveAgyCli` 排除桌面端 GUI 可执行文件**：
   - Windows 平台候选可执行文件名收敛为仅 `['agy.exe']`（不再在 `PATH` 中匹配 `'antigravity.exe'`），避免误将 `%LOCALAPPDATA%\Programs\Antigravity\Antigravity.exe` 当作 CLI 调用。
2. **登录缺 CLI 报错明确区分 App 与 CLI**：
   - [loginManager.ts](../../src/main/accounts/loginManager.ts) 未找到 CLI 时的文案统一明确带 `CLI`（Antigravity 显示 `未检测到 Antigravity CLI（agy），请先安装 Antigravity CLI 后再登录。`）。
