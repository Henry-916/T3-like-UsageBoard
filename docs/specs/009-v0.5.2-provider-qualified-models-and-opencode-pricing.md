# T3-like UsageBoard v0.5.2 规范（按上游 Provider 拆分模型统计与读取 OpenCode 本地定价）

本规范针对 `v0.5.1` 实机使用中发现的「OpenCode 同名模型跨不同上游 Provider（如 `alibaba-cn/qwen3.8-flash`、`cpa/qwen3.8-flash`、`opencsg/qwen3.8-flash`）合并统计且误套定价」问题，梳理并定义 `v0.5.2` 的完整改造方案与验收标准。

- **版本目标**：`0.5.2`（需同步更新 [package.json](../../package.json) `version` 为 `"0.5.2"`）
- **主旨**：
  1. **顶层保持 4 大客户端不变，底层按上游渠道拆分**：继续保留 `Antigravity`、`OpenCode`、`Codex`、`Claude Code` 四个顶层提供方；在用量记录、聚合桶、明细表、模型详情弹窗与自定义价格中，对带渠道标识的记录统一使用小写渠道前缀 `<provider>/<model>`（如 `cpa/qwen3.8-flash`）拆分展示与统计；
  2. **顺手兼容 Codex 自定义 `model_provider`**：Codex 默认 `openai` 维持裸模型名不变，若配置了非 `openai` 的自定义 `model_provider` 同样拼为 `<provider>/<model>`；
  3. **只读读取 OpenCode 本地配置与目录缓存定价**：自动解析本机 `opencode.json` / `opencode.jsonc`（含数组阶梯定价与对象定价）及 OpenCode `models.json` 缓存，且支持保存后刷新热生效；
  4. **严格按渠道隔离计价（未定价不估算）**：绝不将未知/中转渠道的模型剥离前缀去套用裸模型 LiteLLM 单价；未在 UsageBoard 自定义价格、OpenCode 本地配置或明确已知官方按量网关命中单价的模型，一律标记为 `未定价`（`costSource: 'unpriced'`，`costUsd: 0`）。

---

## 硬性安全与隐私红线（所有改动与验收必须遵守）

1. **只读且脱敏解析 OpenCode 配置**：读取 `opencode.json` / `opencode.jsonc` / `models.json` 时，**严禁**读取、缓存、记录、打印或向渲染进程传递 `apiKey`、`headers`、`baseURL`、`options` 等字段；解析器仅提取 `provider` / `providers` 下的模型 ID 与 `cost` 数值结构。
2. **防御性保护 `~/.t3`**：继续保留 [cli.ts](../../src/main/limits/probes/cli.ts) 与 [switchAccount.ts](../../src/main/accounts/switchAccount.ts) 对 `~/.t3` 的隔离护栏，严禁写入、修改或删除 `~/.t3` 下任何文件。
3. **保护参考原图与零实弹兑换**：`docs/references/` 原图不得改动；任何自动化测试与实机验收严禁触发真实 Codex 重置券兑换；测试夹具与日志严禁出现真实个人邮箱或密钥。

## 1. 上游 Provider 前缀标识、归一化与缓存失效

### 1.1 OpenCode 解析器（[src/main/usage/readers/opencode.ts](../../src/main/usage/readers/opencode.ts)）
1. 提取原始渠道与模型：
   - `providerId = (text(modelReference.providerID) || text(message.providerID)).trim().toLowerCase()`
   - `rawModel = (text(modelReference.id) || text(modelReference.modelID) || text(message.modelID)).trim()`
2. 构造渠道限定模型名 `qualifiedModel`：
   - 若 `providerId` 为空（例如无 `providerID` 的旧离线 JSON），保持 `rawModel` 不变；
   - 若 `providerId` 非空：
     - 若 `rawModel` 已带有大小写不敏感的 `${providerId}/` 前缀（例如 `providerId === "openai"` 且 `rawModel === "OpenAI/gpt-5.6-luna"`），规整前缀为小写 `${providerId}/${rawModel.slice(providerId.length + 1)}`（避免拼接出 `openai/openai/...`）；
     - 否则拼为 `${providerId}/${rawModel}`（若 `rawModel` 自身携带上游子路径，如 `openrouter` 下的 `google/gemini-4-neon`，保留子路径拼为 `openrouter/google/gemini-4-neon`）。
   - 将构造结果写入 `UsageRecord.model`（移除原先仅对 `opencode-go` 写入 `rateModel` 的局部特例，统一交由第 2 节查价管道按 `<provider>/<model>` 路由）。
3. 免费模型零费判定：
   - 基于剥离渠道前缀后的裸模型名 `bareModel` 判断免费标识：`OPENCODE_GATEWAYS.has(providerId) && bareModel.endsWith("-free")`；
   - 仅当 `cost > 0` 或满足上述 `-free` 条件且 `cost === 0` 时保留 `reportedCostUsd`；其余 `cost === 0` 维持 `reportedCostUsd: null`，以便用户事后在 `opencode.jsonc` 或 UsageBoard 补配单价时能够正常重算费用。

### 1.2 Codex 非默认 `model_provider` 兼容（[src/main/usage/readers/codex.ts](../../src/main/usage/readers/codex.ts)）
- `session_meta.payload.model_provider` 转小写并去首尾空格记为 `normalizedProvider`：
  - 若 `normalizedProvider === "" || normalizedProvider === "openai"`：保持现有裸 `model` 不变（维持与官方 Codex 视图及 LiteLLM 裸名一致）；
  - 若为其他非空自定义渠道（如 `"cpa"`、`"openrouter"`）：按与 1.1 相同的防重复前缀规则拼为 `${normalizedProvider}/${model}`。

### 1.3 模型归一化（[src/shared/modelNormalize.ts](../../src/shared/modelNormalize.ts)）
- 更新 `normalizeModelId(provider, rawModel)`：
  - 若 `rawModel.trim()` 不含 `/`，保持现有逻辑不变（含 `provider === "antigravity"` 路由映射与最多两层 `effortSuffix` 剥离）；
  - 若包含 `/`：
    - 拆分首段渠道前缀 `prefix = trimmed.slice(0, slash).toLowerCase()` 与右侧模型部分 `rest = trimmed.slice(slash + 1).trim()`；
    - 若 `rest` 非空，仅对 `rest` 剥离最多两层 `effortSuffix`（并确保 `rest` 不会被剥为空串），重新拼回 `${prefix}/${normalizedRest}`（例如 `CPA/gemini-3.8-flash-high` → `cpa/gemini-3.8-flash`，`cpa/claude-opus-5-thinking-high` → `cpa/claude-opus-5`）。

### 1.4 扫描缓存升版（[src/main/usage/scanCache.ts](../../src/main/usage/scanCache.ts)）
- 将 `cacheVersion` 从 `2` 递增至 `3`：
  - 升级后首次扫描自动丢弃不含 `<provider>/` 前缀的旧 `scan-cache.json`，确保已存在的 `opencode.db` / Codex 会话重新提取 `providerID` / `model_provider`。

## 2. 读取本机 OpenCode 定价与严格按渠道隔离计价

### 2.1 新建 OpenCode 本地定价加载器（[src/main/usage/opencodePricing.ts](../../src/main/usage/opencodePricing.ts)）

提供 `loadOpenCodePricing({ home, env }): Promise<{ userRates: RateTable; catalogRates: RateTable }>`，支持依赖注入 `home` / `env` 以便单元测试完全隔离本机环境。

1. **用户配置文件探测与合并顺序（生成 `userRates`）**：
   - 按**低优先级到高优先级**顺序合并（后读取的同名 `provider/model` 覆盖前者）：
     1. 候选目录（按路径大小写规范化去重）：
        - `~/.config/opencode`
        - `$XDG_CONFIG_HOME/opencode`（若已设置）
        - `%APPDATA%\opencode`（仅 Windows 且已设置 `APPDATA`）
        - `$OPENCODE_CONFIG_DIR`（若已设置）
        在每个目录下依次检查 `opencode.json` 与 `opencode.jsonc`（同目录下 `.jsonc` 覆盖 `.json`）；
     2. `$OPENCODE_CONFIG`（若已设置且指向具体文件，最高配置优先级）。
   - **JSONC 安全解析**：
     - 编写字符级状态机剥离 `//` 单行注释、`/* ... */` 多行注释与尾随逗号（`, }` / `, ]`），**严禁**使用会破坏字符串字面量中 URL（如 `https://...`）的简单正则。
     - 任一配置文件缺失、无法读取或 JSON 解析失败时静默跳过，不得拖垮整体用量扫描。
   - **字段脱敏提取**：
     - 仅读取顶层 `provider` 与 `providers` 映射；对每个 `pid` 下 `models` 对象里的每个条目 `mid -> mval`，仅提取 `mval.cost` 与可选字符串 `mval.id`。
     - 忽略非对象项与无效负数，**严禁**读取或保留其他字段。

2. **OpenCode 官方模型目录缓存（生成 `catalogRates`）**：
   - 按顺序探测 `$XDG_CACHE_HOME/opencode/models.json`、`~/.cache/opencode/models.json`、`$LOCALAPPDATA/opencode/models.json`（去重后读取存在且有效的 JSON）；
   - 遍历顶层 `[pid].models[mid].cost`，复用同一套 `cost` 解析器生成 `${pid.toLowerCase()}/${mid.toLowerCase()}` 费率表。

3. **兼容 OpenCode 全部 `cost` 格式（单位均为美元 / 百万 token，需除以 `1e6` 转为单 token 费率）**：
   - **格式 A（对象格式）**：
     ```json
     {
       "input": 0.32656,
       "output": 1.30625,
       "cache": { "read": 0.00594, "write": 0.4 },
       "cache_read": 0.00594,
       "cache_write": 0.4,
       "tiers": [ ... ],
       "context_over_200k": { "input": ..., "output": ..., "cache_read": ... }
     }
     ```
     - 缓存读取单价兼容 `cost.cache?.read` 与 `cost.cache_read`；缓存写入单价兼容 `cost.cache?.write` 与 `cost.cache_write`；
     - 缺失 `cacheRead` 或 `cacheWrite` 时回退为同档位 `input` 单价（`cacheWrite1h` 回退 `cacheWrite`），与 `createOverrideRateTable` 语义保持一致；
     - 存在 `tiers`（数组）或 `context_over_200k`（等效 `threshold = 200_000`）时，转换为 `ModelRate.tiers` 并按 `threshold` 降序排列。
   - **格式 B（数组阶梯格式，OpenCode 实机常见格式）**：
     ```json
     [
       { "input": 1, "output": 5, "cache": { "read": 0.05, "write": 1.25 } },
       { "tier": { "type": "context", "size": 272000 }, "input": 2, "output": 7.5, "cache": { "read": 0.1, "write": 2.5 } }
     ]
     ```
     - 无 `tier` 的元素作为基础 `standard` 费率（若数组全部元素都带 `tier` 则忽略该无效条目）；
     - 含 `tier.type === "context"` 且 `tier.size` 为正有限数字的元素，转为 `ModelRate.tiers` 对应条目并按 `threshold` 降序排列。
   - 键名写入规则：按 `${pid.toLowerCase()}/${mid.toLowerCase()}` 写入；若 `mval.id` 为非空字符串且小写与 `mid.toLowerCase()` 不同，同时写入 `${pid.toLowerCase()}/${mval.id.trim().toLowerCase()}`。

4. **轻量指纹缓存与热生效**：
   - 缓存最近一次读取的所有候选文件路径与 `(mtimeMs, size)` 指纹（不存在的文件记为 `missing`）；
   - [service.ts](../../src/main/usage/service.ts) 在每次 `getSummary` 聚合前调用 `loadOpenCodePricing` 校验指纹，文件有变更时即时重读（因此用户在 `opencode.jsonc` 保存定价后，无需重启 UsageBoard，切换视角或点击刷新即可立即生效）。

### 2.2 严格按渠道隔离的查价优先级（[src/main/usage/pricing.ts](../../src/main/usage/pricing.ts)）

重构 `priceUsage`（接受扩展上下文 `{ overrides, opencodeUserRates, opencodeCatalogRates }` 或等价封装结构，保持对现有 3 参数调用的向后兼容）：

1. **第 1 优先级 — UsageBoard 自定义价格（`overrides`）**：
   - 按 `keyFor(record.model)` 精确匹配（`PriceOverrides` 映射键构建时按小写索引）；
   - **覆盖旧日志**：命中用户显式配置的 `overrides` 时，直接按 `listCost` 与四分类费用返回 `costSource: "modelPriced"`（`categoryCostUsd` 按单价计算），不再受制于历史日志写入时记录的旧 `reportedCostUsd`（例如历史记录写了错误或 `0` 的 `cost`，现在补配单价后立即生效）。
2. **第 2 优先级 — OpenCode 用户配置单价（`opencodeUserRates`）**：
   - 当 `record.provider === "opencode"` 或 `record.model.includes("/")` 时，按 `keyFor(record.model)` 在 `opencodeUserRates` 中精确匹配 `${provider}/${model}`；
   - **覆盖旧日志**：与 `overrides` 相同，命中用户在 `opencode.jsonc` / `opencode.json` 显式配置的单价时，优先按用户配置单价重算费用（`costSource: "modelPriced"`），使补配单价后历史用量可立即重算。
3. **第 3 优先级 — OpenCode 目录缓存（`opencodeCatalogRates`）**：
   - 按 `keyFor(record.model)` 在 `opencodeCatalogRates` 中精确匹配 `${provider}/${model}`；命中后按常规逻辑处理（有正值 `reportedCostUsd` 则按四分类比例缩放）。
4. **第 4 优先级 — LiteLLM 价格表（`table`）**：
   - **不含 `/` 的模型**（Antigravity、Claude Code、默认 Codex、无渠道旧记录）：保持现有 `rateModel` + `lookupRate(table, record.model)` 逻辑不变；
   - **含 `/` 的渠道限定模型 `<provider>/<rest>`**：
     - **严禁**无条件剥离 `<provider>/` 回退去查裸模型名！
     - 仅当 `<provider>` 位于以下**已知官方按量网关白名单**内时，按映射前缀在 `table` 中查找对应费率（支持 `rest` 内含子路径，并经过 `unpriceable` 校验）：
       - `opencode-go` → `opencode_go/<rest>`
       - `opencode` → `opencode/<rest>`
       - `google` → `gemini/<rest>`
       - `google-vertex` → `vertex_ai/<rest>`
       - `alibaba-cn` / `alibaba` / `dashscope` → `dashscope/<rest>`, `qwen_ai_platform/<rest>`, `qwencloud/<rest>`
       - `openai` → `openai/<rest>`, `<rest>`（经 `lookupRate`）
       - `anthropic` / `claude-code` → `anthropic/<rest>`, `anthropic.<rest>`, `<rest>`（经 `lookupRate`）
       - `deepseek` → `deepseek/<rest>`, `<rest>`
       - `xai` → `xai/<rest>`, `<rest>`
       - `mistral` → `mistral/<rest>`, `<rest>`
       - `azure` → `azure/<rest>`, `azure_ai/<rest>`
       - `amazon-bedrock` / `bedrock` → `bedrock/<rest>`, `bedrock_mantle/<rest>`
       - `openrouter` → `openrouter/<rest>`
       - `github-copilot` → `github_copilot/<rest>`
       - `groq` → `groq/<rest>`
       - `perplexity` → `perplexity/<rest>`
       - `deepinfra` → `deepinfra/<rest>`
       - `togetherai` → `together_ai/<rest>`
       - `fireworks-ai` → `fireworks_ai/<rest>`
       - `nebius` → `nebius/<rest>`
       - `novita` → `novita/<rest>`
       - `baseten` → `baseten/<rest>`
     - **未知或第三方中转渠道**（如 `cpa`、`mytokk`、`yundu`、`uuapi`、`opencsg`、`antigravity-designer-bridge` 等）：若第 1~3 步均未命中，**直接返回无单价（`!rate`）**。
5. **未定价兜底**：
   - 当 `!rate` 时，沿用 `v0.5.1` 规则：除明确标注 `$0` 免费模型（`reported === 0`）外，一律返回 `{ costUsd: 0, costSource: "unpriced", categoryCostUsd: null, speedPremiumUsd: 0, cacheSavingsUsd: 0 }`。

## 3. 别名大小写容错与前端明细/自定义价格衔接

### 3.1 聚合与别名解析（[src/main/usage/aggregation.ts](../../src/main/usage/aggregation.ts)）
- `resolveModelAliases(aliases)` 在保留原精确匹配的基础上增加小写键回退映射：如果用户在自定义价格中填写了 `CPA/qwen3.8-flash` → `alibaba-cn/qwen3.8-flash`，即使记录已规范为 `cpa/qwen3.8-flash`，也能正确命中别名映射。
- `aggregateUsage` 聚合键仍为 `[day, hourStart, record.provider, model]`；由于 `model` 已携带 `<provider>/<model>`，同提供方（如 `opencode`）下相同模型的不同上游渠道自动拆分为独立聚合桶。
- 在 [src/main/usage/service.ts](../../src/main/usage/service.ts) 中，将 `loadOpenCodePricing({ home, env })` 接入 `getSummary` 聚合前流程（并将结果传入 `aggregateUsage`）。

### 3.2 明细表、模型详情弹窗与自定义价格弹窗
- [BreakdownTable.tsx](../../src/renderer/components/BreakdownTable.tsx) 的 `ModelTable` 按 `[bucket.provider, bucket.model]` 分组并直接显示 `model.model`（即 `cpa/qwen3.8-flash`、`alibaba-cn/qwen3.8-flash`），同一模型在不同渠道下独立成行展示各自的费用、占比、`未定价` 状态与 Token 数。
- [UsageModelDialog.tsx](../../src/renderer/components/UsageModelDialog.tsx) 标题直接展示带渠道前缀的模型名（如 `cpa/qwen3.8-flash`），未定价时点击「设置价格」向 [PriceOverridesDialog.tsx](../../src/renderer/components/PriceOverridesDialog.tsx) 传入完整 `modal.model.model`（`cpa/qwen3.8-flash`），使保存的 `priceOverrides` 或 `modelAliases` 精准作用于该渠道而不污染其他渠道。
- [PriceOverridesDialog.tsx](../../src/renderer/components/PriceOverridesDialog.tsx) 中 `overrideIds` 唯一性校验继续按 `model.toLowerCase()` 执行，确保 `cpa/qwen3.8-flash` 与 `alibaba-cn/qwen3.8-flash` 可同时各自独立配置不同单价；`<datalist>` 自动补全候选来自 `seenModels`，自然包含所有已扫描到的 `<provider>/<model>`。
