## 1. 修复 Antigravity 历史费用与 Token 漏扫（历史扫描与额度开关解耦）

### 1.1 根因分析
本机实测同一 `7 天`（`11月18日 ~ 11月24日`）窗口内：
- **OpenCode / Codex / Claude Code** 两端数据完全一致（OpenCode `147` 会话 / `1.17B` / `US$145.60`，Codex `US$0.06`，Claude Code `US$0.02`）。
- **Antigravity** 差距来源：
  - 用户在「账号管理」中禁用了 3 个「本机」原生 Antigravity 条目（`~/.gemini/antigravity`、`~/.gemini/antigravity-cli`、`~/.gemini/antigravity-ide`，共 478 个对话 `.db`），以避免它们与 3 个 T3 OAuth 账号（`Antigravity-Fofinha`、`Antigravity-Henry916`、`Antigravity-yifan`）在「限制」页重复或报错。
  - 当前 [service.ts](src/main/usage/service.ts#L107) 在扫描历史用量目录时写了 `if (!account.enabled || account.provider !== provider || !account.dataDir) continue`，把原本只应控制「实时额度探测（Limits）」的 `enabled` 开关误用到了历史扫描上，导致 478 个本地 `.db` 被跳过，只扫描到 `~/.t3/userdata/providers/antigravity/*/antigravity-acp` 下由 T3 发起的 `8` 个小会话（`667K token / US$1.33`）。
  - 对照 T3 Code 源码（`C:\Users\24701\AppData\Local\Temp\t3code-src\apps\server\src\usage\UsageService.ts` L370–L374 与 `AntigravityUsage.ts` L49–L62）：T3 无论账号实例是否启用，始终扫描各驱动的默认本地目录与实例目录，历史统计不被实例开关隐藏。

### 1.2 实现要求
- 修改 `src/main/usage/service.ts` L107：
  ```ts
  if ((account.origin === 'manual' && !account.enabled) || account.provider !== provider || !account.dataDir) continue
  ```
  说明：
  - `origin === 'native'` 与 `origin === 't3'`（受 `config.scanT3` 总开关控制）的数据目录**始终参与历史用量扫描**，不再受 `accountPreferences[id].enabled` 影响；
  - 仅用户通过「账号管理」手动添加且显式关闭（`account.origin === 'manual' && !account.enabled`）的自定义目录继续跳过历史扫描；
  - `src/main/limits/service.ts` 与 `src/main/accounts/discovery.ts` **保持不变**，已关闭的本机条目在「限制」页仍保持关闭，不参与额度探测。
- 新增单元测试（`tests/usageService.test.ts`）：
  - 构造一个带本地日志的 `native` 账号与一个手动目录账号（`origin: 'manual'`），两者均在 `accountPreferences` 中设为 `{ enabled: false }`；
  - 断言 `getSummary()` 仍包含 `native` 账号的历史统计，同时排除被禁用的 `manual` 目录。

## 2. 窗口右上角新增「最大化 / 向下还原」按钮

### 2.1 主进程与 IPC 协议
参考 T3 Code 的状态同步思路（点击按钮、双击标题栏拖拽区、系统快捷键 `Win + ↑/↓` 状态保持一致）：
1. **`src/shared/ipc.ts`**：
   - `usageChannels` 新增：
     ```ts
     toggleMaximize: 'usage:window-toggle-maximize',
     isMaximized: 'usage:window-is-maximized',
     maximizedChanged: 'usage:window-maximized-changed',
     ```
   - `UsageApi` 新增：
     ```ts
     toggleMaximize(): Promise<boolean>
     isMaximized(): Promise<boolean>
     onMaximizedChanged(listener: (maximized: boolean) => void): () => void
     ```
2. **`src/preload/index.ts`**：
   - 暴露 `toggleMaximize`、`isMaximized`、`onMaximizedChanged`（参照 `onLimitsUpdated` 返回取消订阅函数）。
3. **`src/main/ipc.ts`**：
   - 注册 `usageChannels.isMaximized`：返回 `window.isMaximized() || window.isFullScreen()`。
   - 注册 `usageChannels.toggleMaximize`：若 `window.isFullScreen()` 则调用 `window.setFullScreen(false)`；否则在 `window.unmaximize()` 与 `window.maximize()` 间切换；最终返回 `window.isMaximized() || window.isFullScreen()`。
4. **`src/main/index.ts`**：
   - 在 `createPanel()` 中监听 `maximize`、`unmaximize`、`enter-full-screen`、`leave-full-screen` 事件，窗口与 `webContents` 未销毁时通过 `window.webContents.send(usageChannels.maximizedChanged, window.isMaximized() || window.isFullScreen())` 同步给渲染进程。

### 2.2 前端交互与图标细节
1. **`src/renderer/main.tsx`**：
   - 增加 `maximized` 状态（初始 `false`），挂载时调用 `window.usageApi.isMaximized?.()` 初始化并订阅 `window.usageApi.onMaximizedChanged?.(setMaximized)`（注意兼容测试环境可能未挂载完整 `window.usageApi` 的可选链调用）。
   - 将 `runWindowAction` 扩展为 `'minimize' | 'toggleMaximize' | 'hide'`，并在失败时设置清晰错误提示；向 `<TopBar />` 传入 `maximized={maximized}`。
2. **`src/renderer/components/TopBar.tsx`**：
   - 在 `.window-controls` 内「最小化」与「关闭到托盘」之间插入最大化/向下还原按钮：
     - `type="button"`、`className="icon-button"`
     - `aria-label={maximized ? '向下还原' : '最大化'}`、`title={maximized ? '向下还原' : '最大化'}`（避免同时叠加 `aria-pressed` 与动态 `aria-label` 造成语义冲突）
     - 使用 `15×15` 居中 SVG（`viewBox="0 0 16 16" fill="none" aria-hidden="true" stroke="currentColor" strokeWidth="1.4"`）：
       - 默认态（最大化）：单个圆角方框 `<rect x="2.75" y="2.75" width="10.5" height="10.5" rx="1.5" />`
       - 已最大化/全屏态（向下还原）：Windows 11 前后重叠双圆角方框（前景 `<rect x="2.5" y="4.75" width="8.75" height="8.75" rx="1.4" />` + 后景遮挡描边 `<path d="M5.25 4.75V3.9A1.4 1.4 0 0 1 6.65 2.5h5.45A1.4 1.4 0 0 1 13.5 3.9v5.45a1.4 1.4 0 0 1-1.4 1.4h-.85" />`）。
3. **`src/renderer/styles/globals.css`**：
   - 在 `.icon-button` 中补充 `min-inline-size: 30px; min-block-size: 30px;`，保证按钮热区不因布局压缩小于 30px。

## 4. 调整 Antigravity 额度条显示顺序（按模型家族分组）

### 4.1 问题说明
当前 `src/shared/usageLimits.ts` 第 155 行末尾仅按 `.sort((a, b) => KIND_ORDER[a.kind] - KIND_ORDER[b.kind])` 排序，导致 Antigravity 窗口按时长拆散交错为：
`Gemini · 5-hour` → `Claude & GPT (shared) · 5-hour` → `Gemini · Weekly` → `Claude & GPT (shared) · Weekly`。

### 4.2 实现要求
对照 T3 Code `C:\Users\24701\AppData\Local\Temp\t3code-src\packages\shared\src\usageLimits.ts` 第 537–547 行 `displayLimitWindows` 的排序规则，在 `src/shared/usageLimits.ts` 第 155 行的 `poolUsageLimits` 输出排序中改为按模型家族优先分组：
```ts
  }).sort((a, b) => {
    if (a.provider === 'antigravity' && b.provider === 'antigravity') {
      const geminiOrder = Number(!a.windowId.startsWith('gemini-')) - Number(!b.windowId.startsWith('gemini-'))
      if (geminiOrder !== 0) return geminiOrder
      const familyOrder = a.windowId
        .replace(/-(?:5h|weekly|quota)$/, '')
        .localeCompare(b.windowId.replace(/-(?:5h|weekly|quota)$/, ''))
      if (familyOrder !== 0) return familyOrder
    }
    return KIND_ORDER[a.kind] - KIND_ORDER[b.kind]
  })
```
期望最终呈现顺序（与 T3 一致）：
1. `Gemini · 5-hour`
2. `Gemini · Weekly`
3. `Claude & GPT (shared) · 5-hour`
4. `Claude & GPT (shared) · Weekly`
（若出现 `gemini-argon-*` / `gemini-carbon-*` 等子家族，同样先各自把 `5-hour` 与 `Weekly` 相邻成组，再排 `3p-*`。）

- 新增单元测试（`tests/usageLimits.test.ts`）：
  - 构造同时含 `gemini-5h`、`3p-5h`、`gemini-weekly`、`3p-weekly` 的 Antigravity 读数，断言 `poolUsageLimits` 返回的 `windowId` 顺序严格为 `['gemini-5h', 'gemini-weekly', '3p-5h', '3p-weekly']`；
  - 额外覆盖 `gemini-carbon-weekly` / `gemini-argon-5h` 与 `3p-*` 混排场景，确保同家族 `5-hour` 排在 `Weekly` 前且不与其他家族交错。
