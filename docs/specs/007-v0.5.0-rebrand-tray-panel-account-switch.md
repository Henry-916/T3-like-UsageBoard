# T3-like UsageBoard v0.5.0 规范（更名与新 Logo、分类条重设计、邮箱显示与快捷切号、托盘额度小面板）

本规范汇总并与 Henry 对齐 `v0.5.0` 的全部需求，交由 GPT 按节落地实现与验收。

- **版本目标**：`0.5.0`
- **主旨**：
  1. 产品更名为 **T3-like UsageBoard**（仓库/目录 `T3-like-UsageBoard`），重绘专属 Logo、`userData` 无损迁移及发版后工作区与会话库改名脚本；
  2. 重设计「按类型统计的费用 / token」条带（修正文案、改用「未拆分」斜纹、拉开四档灰度并增加 2px 黑缝）；
  3. 账号显示名不可编辑并统一等同于账号邮箱（OpenCode Go 固定为 `OpenCode Go`），按邮箱合并去重并重排账号管理列表行，同时移除限额详情浮层中的「来源」条目；
  4. 为 **Codex** 与 **Antigravity（App / CLI）** 增加带二次确认与防轮换冲突的「设为当前」快捷切号功能；
  5. 托盘左键单击弹出贴近任务栏的独立额度小面板（双击与单击一致不做多余切换），「显示主面板」留在托盘右键菜单第一项；
  6. 附带一次性运维任务：将 Henry 本机 T3 中有效的三个 Antigravity OAuth 账号迁移导入新版应用内存储。

## 硬性安全红线（所有改动与验收必须遵守）

沿用 [CURRENT.md](../CURRENT.md) 第 3 节并按本版决定修订：
1. **只读保护 `~/.t3`**：严禁写入、修改或删除 `~/.t3` 下任何文件；严禁对 `origin === 't3'` 或解析指向 `~/.t3` 的别名目录拉起可能写回目录状态的外部 CLI。
2. **保护参考原图**：`docs/references/` 下所有参考截图始终保留无损原图，不得有损压缩或改动。
3. **零实弹兑换 Codex 重置券**：任何自动化测试、人工脚本或冷启动验收均**禁止**触发真实的 Codex 重置券兑换。
4. **隐私脱敏边界（v0.5.0 修订）**：**应用 UI（账号管理、额度条、详情浮层、托盘小面板）展示账号邮箱**；终端输出、日志、文档、工单与测试夹具中仍**严禁**出现真实邮箱、`access_token`、`refresh_token`、授权码或 API Key，自动化测试统一使用 `@example.com` 占位邮箱。

### A.2 `userData` 目录与无损迁移
- 新版用户数据目录路径应为 `%APPDATA%\t3-like-usageboard`。
- **执行前确认**：先确认打包后 Electron `app.getName()` 实际取的是 `package.json` 的 `name`（`t3-like-usageboard`）还是 `electron-builder` 注入的 `productName`；必要时在 `app` `ready` 事件触发前显式调用：

  确保开发态与打包态一致落盘至 `%APPDATA%\t3-like-usageboard`。
- **首次启动自动迁移**：
  - 若新目录 `%APPDATA%\t3-like-usageboard` 中尚不存在 `config.json`，且旧目录 `%APPDATA%\usage-dashboard` 存在，则在初始化配置与 `safeStorage` 读数之前，将旧目录内容递归复制到新目录：

    - **旧目录 `%APPDATA%\usage-dashboard` 保留不删除**，作为回退备份。
  - **单元测试覆盖**：至少覆盖三种场景——(1) 首次迁移复制成功（含 `Local State` 与 `config.json`，跳过缓存目录）；(2) 新目录已存在 `config.json` 时不覆盖；(3) 旧目录不存在时不报错。

## C. 账号显示名强制为邮箱 + 列表去重合并 + 账号行重排

### C.1 显示名规则
- **所有账号展示位置统一改为账号邮箱**（账号管理列表、限制页额度条内部账号名、限额详情浮层标题、托盘小面板），**不可编辑**。
- 移除「账号管理」列表中的编辑铅笔图标及改名表单/接口，「添加账号」表单不再让用户输入或依赖自定义显示名（底层若旧配置仍含 `displayName` 字段可保留以向后兼容，但 UI 不再优先渲染）。
- 超长邮箱在紧凑容器内做单行省略（`text-overflow: ellipsis`），完整邮箱置于元素 `title` 属性便于悬停查看。

### C.2 各提供方邮箱提取与持久化缓存
- **发现与提取来源**：
  - **Antigravity（含 Windows 凭据管理器当前槽位）**：
    - Windows 下账号发现层需额外通过 `CredReadW("gemini:antigravity", 1)` 读取当前系统凭据槽（例如作为 `native:antigravity:credman`），只要能按 UTF-8 解析为合法 `cliToken` JSON 即视为当前激活（带「**当前**」标记）的 Antigravity 账号，参与合并、展示与实时额度探测（其日常刷新按 E.1 防轮换冲突策略直接面向当前激活槽位读写，并冻结应用内副本）；
    - **邮箱提取**：优先直接读取 `cliToken` JSON 顶层的 `id_token_email`（规范化小写，离线立即可得），并在 [antigravity.ts](../../src/main/limits/probes/antigravity.ts) 既有的 `https://www.googleapis.com/oauth2/v2/userinfo` 请求中同步解析 `email` 字段作校验与兜底写入 `identities.json`（token scope 已包含 `userinfo.email`）；
  - **Codex**：从对应 `auth.json` 的 `tokens.id_token` 解码 JWT payload（仅解析 JSON payload，不泄露密钥），提取 `email`（或 `https://api.openai.com/profile` 对象中的 `email`）；
  - **Claude Code**：沿用 [claude.ts](../../src/main/limits/probes/claude.ts) 中既有的 `oauthAccount.emailAddress` / `profile.email`；
  - **OpenCode（Go API Key）**：无邮箱信息，固定显示 `OpenCode Go`。
- **持久化身份缓存（例如 `userData/identities.json`）**：
  - 按 `account.id`（及解析路径）持久化已识别的规范化邮箱，保证冷启动打开「账号管理」即可直接渲染邮箱，无需等待本轮线上额度探测结束。
  - 若账号刚添加或尚未取到过邮箱：探测进行中显示「**正在识别…**」，探测失败且无缓存时显示「**未知账号**」。

### C.3 同提供方按邮箱合并与账号行新布局
- **去重合并规则**：
  - 在账号管理列表与实时额度探测队列中，同一 `provider` 下将**规范化小写后相同的邮箱**合并为单一账号行：
    - 代表优先级：优先选用 `origin === 'manual'`（应用内账号）作为代表，若无应用内账号则选用默认目录 / 系统凭据槽 / 其它已有凭证来源；
    - 只要关联凭证中的某一来源是当前本机激活位置（Codex 为默认 `auth.json`，Antigravity 为 Windows 凭据槽 `gemini:antigravity`），该行即带有「**当前**」标记；
    - 当同一账号既存在默认激活登录态又存在应用内副本时，参见 **E 节「防刷新冲突策略」**。
  - **历史用量扫描不受合并或启用状态影响**：继续严格遵守 [CURRENT.md](../CURRENT.md) 第 2.2 节「历史统计 vs 实时额度解耦」，`native` 与启用 `scanT3` 下的 `t3` 历史目录始终完整计入费用与 Token。
- **账号行布局（按 Henry 确认方案）**：
  - **左侧**：保留提供方图标 `<ProviderMark />`；
  - **主信息区两行**：
    - **第一行**：提供方名称（如 `Antigravity`、`Codex`、`Claude Code`、`OpenCode`）；
    - **第二行**：账号邮箱（或 `OpenCode Go`）+ 紧随其后的「**当前**」小胶囊标记（仅当该账号正位于对应激活位置时显示）；
  - **移除元素**：彻底删掉「原生 / T3 / 应用内」来源标签、文件系统目录路径行以及编辑铅笔图标。
  - **右侧操作区**：保留启用开关（Toggle）、删除/移除按钮；对于非当前激活账号，属于 `Codex` 或持有 `cliToken` 结构凭证的 `Antigravity` 行（含应用内 `agy acp --login`、`gemini:antigravity` 快照及从 T3 迁移导入的 `antigravity-oauth-token` 账号；仅含 `acp_token.json` 的 Antigravity 行不展示）额外提供「**设为当前**」按钮。

## E. 快捷切换账号（「设为当前」，支持 Codex 与 Antigravity App/CLI）

- **范围约束**：仅出现在主面板「账号管理」弹窗中；仅对 **Codex** 与 **Antigravity（App / CLI `agy`，不管 Antigravity IDE 的 `state.vscdb`）** 启用；**不做 Claude Code 切换**。
- **二次确认弹窗**：
  - 点击「设为当前」时打开独立的二次确认弹窗（复用「使用重置券？」的深色模态样式与无障碍结构，**默认聚焦「取消」按钮**防止误触回车）；
  - 明确提示：**切换账号将写入本机默认凭证并自动重启 Codex / Antigravity App；正在运行的命令行 CLI 会话需要手动重开或刷新**。

### E.1 通用切号流程与防轮换冲突
1. **快照保护当前激活账号**：
   - 先读取该提供方默认激活位置（见下）当前的凭证并识别其邮箱：
     - 若该邮箱**尚未**保存在应用内账号存储中：自动加密创建一份应用内副本，保留原用户的当前登录态不丢失；
     - 若该邮箱**已**存在于应用内存储中：将默认位置中最新鲜的 token（如轮换后的 `refresh_token` / `access_token`）回写同步至应用内副本；
2. **文件/条目备份**：

## F. 系统托盘点击弹出额度小面板

### F.1 托盘交互变更（[tray.ts](../../src/main/tray.ts)）

### F.2 弹出窗口形态与定位
- 新建无边框独立 `BrowserWindow`（仅在需要时创建或常驻隐藏复用以加速弹出）：
  - 宽度约 **`360px`**，高度随内容自适应，**上限 `520px`**（超过 `520px` 时主体列表内部滚动）；

### F.3 小面板内容与样式规范
- 贯彻「**避免不必要的次要标签和描述，让布局本身来传达信息**」，**不要额外叠加无用大标题或宣传副标题**：

  - **无障碍**：遵守 `prefers-reduced-motion`，按钮与交互支持键盘焦点切换。
