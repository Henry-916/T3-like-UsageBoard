## 1. 全局统一唯一官方定价源 `models.dev`（内置同源精简快照 + 在线自动替换）

### 1.1 架构原则
- **彻底废除多套异构价格表与本机软件依赖**：
  - **移除 LiteLLM**：删除 `BerriAI/litellm` 网络请求、`litellm-rates-cache.json` 及旧版 5MB 的 `resources/fallback-rates.json`；
  - **移除本机 OpenCode 目录缓存依赖**：从 [opencodePricing.ts](../../src/main/usage/opencodePricing.ts) 中删除 `opencodeCatalogPaths`（`~/.cache/opencode/models.json`）与 `opencodeDbPaths`（`opencode.db` `models-dev:v3:catalog`）——软件定价能力与用户电脑是否安装 OpenCode 完全解耦（[opencodePricing.ts](../../src/main/usage/opencodePricing.ts) 仅保留只读提取用户在 `opencode.json` / `opencode.jsonc` 中手写的私有渠道 `cost` 覆写 `userRates`）。
- **全应用唯一官方数据源（主计价器与价格预设 100% 同源共享）**：
  - 主计价引擎（[pricing.ts](../../src/main/usage/pricing.ts)）与自定义价格预设列表（[pricePresets.ts](../../src/main/usage/pricePresets.ts)）统一使用**同一套精简目录快照格式**（同时承载全渠道计价费率表与筛选后的原厂/主流渠道预设列表，体积仅数百 KB，**绝不把 12 MB 原始 JSON 直接原样落盘**）；
  - **随包内置同源精简快照 + 在线热替换**：
    1. 在 `package.json` 新增构建维护脚本（如 `pnpm update:models`），从 `models.dev` 拉取并脱敏提炼生成精简快照 `resources/models-dev-snapshot.json`（本次实施时直接生成入库，并将 [electron-builder.yml](../../electron-builder.yml) 的 `extraResources` 由 `fallback-rates.json` 替换为 `models-dev-snapshot.json`）；
    2. **运行时加载策略（首屏 `0ms` 秒开 + 24h 自动保鲜）**：
       - 若 `userData/models-dev-cache.json` 存在且未满 24h TTL，直接读取返回（`status: 'cached'`）；
       - 若本地尚无 `models-dev-cache.json` 或已超 24h TTL：**立即先返回已有本地快照**（优先用过期的 `userData/models-dev-cache.json`，首次安装尚无缓存时用随包内置的 `resources/models-dev-snapshot.json`，实现零等待首屏），同时在后台去重发起在线拉取；
       - 在线拉取成功后，生成同结构的最新精简快照原子替换写入 `userData/models-dev-cache.json`（拉取失败时静默保留内置快照或旧缓存兜底，用户完全无感）。

### 1.2 网络请求、渠道匹配与倍率防坑规则
1. **走主进程 `electron.net.fetch` 自动继承系统代理 + `ETag` 与同源降级**：
   - 因 `worker_threads` 中的原生 Node `fetch` 在 Windows 下忽略系统代理设置，目录 HTTP 请求须由主进程 `electron.net.fetch` 发起（经 worker ↔ main 消息桥接或主进程注入加载器；单测环境无 Electron 时平滑回退全局 `fetch`）；
   - 主请求地址为 `https://models.dev/experimental/v2.0/api.json?type=all`（**严禁附加 `include=openai-codex,openai-chatgpt`**，避免引入 `$0` 订阅伪价格）；携带上次缓存的 `ETag`（`If-None-Match`），命中 `304 Not Modified` 时直接刷新 `fetchedAt` 零流量返回；
   - 若实验路径返回 HTTP 404 / 5xx，自动降级请求同源稳定地址 `https://models.dev/api.json`（同一数据库 v1 格式，解析器保持 v1 / v2 双格式兼容）。
2. **裸模型、网关同义前缀与日期快照回退（严禁未知渠道剥离前缀）**：
   - **裸模型（不含 `/`）**：仅从官方第一方原厂（`openai`、`anthropic`、`google`、`deepseek`、`xai`、`mistral`、`meta`）生成裸模型映射，绝不混入第三方转售渠道单价；
   - **渠道限定模型 `<provider>/<rest>`**：构建目录费率表时同时索引 `<provider>/<modelKey>`、`<provider>/<row.id>`，以及当 `canonical_id` 的 `<owner>` 与 `<provider>` 相同时补充 `<provider>/<canonical_slug>`（使 `deepseek/deepseek-v4.1-flash-1017` 与 `deepseek/deepseek-flash` 同享官方费率与峰谷规则）；查询时优先精确匹配 `models.dev` 中的 `<provider>/<rest>`，仅对客户端同义渠道名做白名单转发：`openai-codex/`、`openai-chatgpt/` → `openai/`，`claude-code/` → `anthropic/`，`dashscope/` → `alibaba-cn/`、`alibaba/`，`bedrock/` → `amazon-bedrock/`；未知/私有中转前缀（如 `custom/`、`cpa/`、`opencsg/`）未配置自定义单价时一律返回 `unpriced`；
   - **快照日期后缀回退**：当精确模型 ID 未命中时，若模型名末尾带有 `-YYYYMMDD` 或 `-YYYY-MM-DD` 快照日期后缀（如 `claude-opus-5-5-20261001`），剥离该日期后缀后再在同一目标渠道下回退查找一次主型号（如 `anthropic/claude-opus-5-5`）。
3. **计价优先级与 `multipliers` 严格白名单**：
   - 优先级：`UsageBoard 自定义价格 (priceOverrides) > OpenCode 用户配置文件手填单价 (opencode.jsonc userRates) > models.dev 统一目录`；
   - `pricingMultipliers.ts` 边界：
     - `record.speed === 'fast'` 同时匹配 `service_tier` 为 `'fast'` 或 `'priority'`，`record.speed === 'ultrafast'` 匹配 `'ultrafast'`；
     - `when` 对象严格执行条件键白名单校验（仅允许 `utc_days`、`utc_hours`、`date`、`service_tier`、`all`、`any`、`not`）：除显式忽略 `not: { holiday: ... }` 调休条件外，凡包含 `region` 等未知条件键的分支一律视为不可满足（丢弃该条规则或返回不命中），**严禁剥离未知键后将特定地区加价误算到所有用户头上**；
     - `describeRecordRate` 生成模型详情 `?` 单价时，对当前日期已生效的纯 `date` 调价倍率同步折算进展示单价（或对尚未生效的 `date` 规则附一行简短说明），确保 `?` 单价表与实际扣费完全一致。

## 2. 峰谷计价：内置目录自动计费 + 预设峰谷预览与同行胶囊开关（零时间表单）

### 2.1 内置目录自动峰谷计费
- 依托统一的 `models.dev` 目录，凡上游已收录时段 `multipliers` 的渠道（如 `deepseek/...`、`alibaba-cn/...`、`siliconflow-cn/...`、`huawei-maas/...` 等），无论来自哪个客户端均自动按 `UsageRecord.timestampMs` 套用峰谷倍率计费，并在模型详情 `?` 浮层表格下方只读展示本地时区峰谷时段与折算后峰谷单价。

### 2.2 自定义模型价格：预设峰谷图标预览 + 点选后同行胶囊开关（摆法 A）
- **移除旧版时间编辑表单**：
  - 彻底删除 [PriceOverridesDialog.tsx](../../src/renderer/components/PriceOverridesDialog.tsx) 中原有的行下「峰谷」文字链接、上下双层 `.price-model-cell`、`<input type="time">` 时间段编辑器与整条 `.price-peak-row` 展开子行，以及 [pricingMultipliers.ts](../../src/shared/pricingMultipliers.ts) 中仅服务于手动时间编辑器的 `localPeakToMultipliers` / `multipliersToLocalDraft`。
- **预设下拉列表：峰谷小图标 + 悬浮展示时段与具体峰谷价格**：
  - `PricePreset` 保留从 `models.dev` 提取的时段 `multipliers?: RateMultiplier[]`；
  - 在预设下拉列表项（`.preset-picker-option`）右侧单价串 **`入 $...` 的正左侧**，为带时段峰谷规则的预设渲染对齐的 `<Clock size={12} />` 峰谷标识图标；
  - 鼠标悬停该峰谷图标时，复用外层 `position: fixed` 防裁切气泡展示具体峰谷规则：**第一行按 `factor > 1` 或 `factor < 1` 显示 `高峰期（2x）` / `低谷期（0.5x）`**，**第二行直接显示乘上对应 `factor` 后的具体峰谷单价**（如 `入 $0.3 · 出 $1.2 · 读 $0.006 · 创 $0.3`），**第三行显示本地峰谷时段**（如 `工作日 9:00–12:00、14:00–18:00` 或 `22:00–8:00`，去掉小时前导 `0` 且不重复尾缀 `×2`），与左侧超长模型名的截断提示互不干扰。
- **点选预设后：「模型 ID」单元格同行内嵌胶囊开关（零额外行高）**：
  - 当用户选中带时段 `multipliers` 的预设时，自动回填 4 项基础单价并带入 `multipliers`（默认开启 `multipliersEnabled = true`）；若改选不带峰谷的预设，则自动清除该行的 `multipliers` 与开关；
  - **同行水平布局**：第 1 列「模型 ID」单元格采用单行水平 `flex` 排列（`align-items: center; gap: 6px; min-width: 0`），左侧为模型 ID 输入框（`flex: 1; min-width: 0`）或已有模型名文本，右侧紧邻紧凑胶囊开关 `<button type="button" role="switch" aria-checked={enabled} className="price-peak-pill">`（内含 `Clock` `11px` 图标 + `峰谷` 字样，`flex: none`），整行高度与右侧 4 个单价输入框、「选择预设」、移除按钮严格水平居中对齐，绝不产生半行错位；
  - **开关状态与实时悬浮预览**：
    - 开启态（`aria-checked="true"`）高亮显示，关闭态（`aria-checked="false"`）弱化置灰，点击即切换开/关并标记 `changed = true`；
    - 悬停或键盘聚焦该胶囊开关时，以 **`position: fixed`** 视口夹紧浮层（脱离 `.price-table-wrap` 滚动容器防裁切，支持按 `Escape` 仅收起气泡不关弹窗）按同样「标题 → 折算单价 → 本地时段」三行结构展示（**按当前行输入框内的实时基础单价 × `factor` 动态计算出具体峰谷单价**；开/关状态直接由胶囊本身的明暗视觉传达，浮层不重复显示 `已关闭`）；
  - **持久化可重开**：`priceOverridesSchema` 保存可选 `multipliers?: RateMultiplier[]` 与 `multipliersEnabled?: boolean`；`createOverrideRateTable` 仅当 `multipliersEnabled !== false` 时挂载倍率参与计费与 `?` 展示，确保用户关闭峰谷并保存后，下次打开弹窗胶囊开关仍保留在关闭态可随时重新开启。

## 4. 模型详情弹窗（`UsageModelDialog`）：标题旁单价表格 + 两阶段极速刷新

### 4.1 模型名称右侧悬浮单价表
- **挂载位置移至标题右侧（[UsageModelDialog.tsx](../../src/renderer/components/UsageModelDialog.tsx)）**：
  - 将 `CircleHelp`（`14px`）问号按钮从 `每百万 token` 旁**移至弹窗头部 `<h2>` 模型名称正右侧**（仅当存在生效单价 `price` 时渲染，同行垂直居中对齐）；
  - **防裁切定位**：浮层采用左对齐起点（如 `left: 0` 或弹窗安全边界夹紧）并确保 `.dialog-header` 层级高于 `.dialog-body`，避免短模型名下被 `.usage-dialog { overflow: hidden }` 裁切左缘；保留 `query.timeZone` 透传与 `Esc` 分级收起逻辑。
- **纯数字单价表格（常规两列 / 峰谷三列，统一左对齐）**：
  - 常规模型表头固定两列：**`类型`** | **`价格（美元/M）`**（各列统一左对齐，`tabular-nums`）；
  - 带单组时段峰谷的模型自动升级为三列表头：**`类型`** | **`峰期（美元/M）`** | **`谷期（美元/M）`**（自动按 `factor > 1` 或 `factor < 1` 将高价归入「峰期」列、低价归入「谷期」列，统一左对齐）；
  - 四行固定为 `输入`、`输出`、`缓存读取`、`缓存创建`，单元格填**不带货币符号的纯数字**（如 `0.283`、`0.1415`；缺失填 `—`）；
  - 表格下方按需附带上下文阶梯价、与表头呼应的峰谷时段说明（如 `峰期：工作日 9:00–12:00、14:00–18:00` 或 `谷期：22:00–8:00`，不标倍率）及 `自定义价格` 标记，不暴露底层数据源技术名称。

### 4.2 单模型两阶段极速刷新 + `opencode.db` 增量游标
1. **两阶段优先刷新（先快刷当前提供方，再后台静默刷其余提供方）**：
   - 扩展 `summary` 查询链路支持可选参数 `refreshProvider?: UsageProviderKind`；
   - 在 `UsageModelDialog` 点击右上角刷新或按 `R` 时：
     - **第一阶段**：worker 仅对 `model.provider` 单个提供方执行增量扫描与合并（其余 3 家复用内存 `snapshot`，无快照时回退全扫），立即返回更新当前模型弹窗并**立即结束弹窗内刷新按钮的转圈禁用态**；
     - **第二阶段**：第一阶段返回后，前端自动在后台静默发起其余提供方刷新以同步主面板全局数据（不重新锁死模型弹窗刷新按钮，并用请求序号防止旧结果覆盖新结果）。
2. **`opencode.db` 增量扫描游标（[scanCache.ts](../../src/main/usage/scanCache.ts) & [readers/opencode.ts](../../src/main/usage/readers/opencode.ts)）**：
   - 在 `scan-cache`（递增缓存版本号）中记录 `opencode.db` 各消息表（`message` / `session_message`）上次已扫最大 `rowid`；当数据库追加写入、文件未截断重建时，仅增量查询 `rowid > lastRowId` 的新消息并与缓存合并去重，消除每次对话后重扫 92 天全表的延迟。
