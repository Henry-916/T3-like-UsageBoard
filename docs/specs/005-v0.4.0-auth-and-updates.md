# UsageDashboard v0.4.0 规格规范（精准凭证发现、账号删除/隐藏、应用内直接登录与自动更新）

本规范面向将 UsageDashboard 分发给其他用户使用的核心场景，完整覆盖四个问题与目标：
1. 解释并消除「账号管理」中出现无凭证原生目录（如 `antigravity`、`antigravity-cli`、`antigravity-ide`）的问题，同时保留全部历史用量扫描；
2. 为所有来源的账号补齐安全的删除 / 隐藏与恢复能力；
3. 支持启动自动扫描本机已登录账号 + 应用内直接发起多账号隔离登录；
4. 基于公开 GitHub Releases 为 NSIS 安装版与单文件便携版分别实现「检查更新并更新」。

> 本文档供 GPT 按模块逐项实现。当前默认 GitHub 发布仓库暂定为 `Henry-916/UsageDashboard`（如用户后续更换仓库名，仅调整 `package.json` 与 `electron-builder.yml` 中的 `owner/repo` 即可）。

## 1. 本机已登录账号精准识别（无凭证目录过滤 + 全量历史保留）

### 1.1 问题根因
1. 当前 [src/main/accounts/discovery.ts](../../src/main/accounts/discovery.ts) 的 `locations('antigravity')` 对 `~/.gemini/{antigravity,antigravity-cli,antigravity-ide,antigravity-backup}` 只要目录存在就无条件产出 `DiscoveredAccount`，哪怕目录里只有对话历史 `.db`、**没有任何登录凭证**；同时却遗漏了原生 Antigravity 实际存放 `acp_token.json` / `antigravity-oauth-token` 的 `~/.gemini/antigravity-acp` 目录。
2. [src/main/accounts/service.ts](../../src/main/accounts/service.ts) 在 `list()` 与 `listInternal()` 中返回了全部 `discover()` 结果，未按 `hasCredential` 过滤无凭证的 `native` / `t3` 条目，导致用户在「账号管理」看到 3 个无凭证 Antigravity 目录以及无 OAuth 额度凭证的实例（如 Vertex 实例或已登出的 `~/.claude`）。
3. 自 `v0.3.1` 起，历史用量扫描已与实时额度开关解耦，历史会话扫描不需要依赖「账号管理」列表中展示这些无凭证目录。

### 1.2 实现要求

#### 1.2.1 `src/main/accounts/discovery.ts`
- 在 `locations('antigravity', ...)` 的 `.gemini` 默认候选列表中，将 `'antigravity-acp'` 放在首位：
  ```ts
  return [
    ...['antigravity-acp', 'antigravity', 'antigravity-cli', 'antigravity-ide', 'antigravity-backup'].map(name => join(home, '.gemini', name)),
    join(home, '.config', 'antigravity')
  ]
  ```
- **保持** `discoverAccounts(config, { home, env })` 继续产出所有存在的 `native`、`t3`（当 `config.scanT3 === true` 时）和 `manual` 数据目录：
  - `src/main/usage/service.ts` 直接调用 `discoverAccounts(config, { home, env })`，不受 `hiddenAccountIds` 或无 OAuth 凭证过滤影响，确保 `~/.gemini/{antigravity,antigravity-cli,antigravity-ide}` 等所有本机历史日志始终纳入费用与 token 统计。

#### 1.2.2 `src/main/limits/probes/opencode.ts`
- 将 `opencode.db` 凭证读取提取并导出复用辅助函数 `hasOpenCodeDbCredential(dataDir?: string): boolean`（或复用 `databaseKeys(dataDir).length > 0`），避免在账号服务中重复编写 SQLite 查询逻辑：
  - 以 `readOnly: true`、`PRAGMA busy_timeout = 100` 检查 `join(dataDir, 'opencode.db')` 的 `credential` 表中是否存在 `integration_id IN ('opencode', 'opencode-go') AND active IS NOT 0` 且有效（`server` 为空或为 `https://opencode.ai/console`）的非空 key。

#### 1.2.3 `src/main/accounts/service.ts`
- 新增内部凭证判定函数 `hasDetectedCredential(account: DiscoveredAccount): Promise<boolean>`：
  - **Antigravity**：
    - 若 `account.limitsEnv?.ANTIGRAVITY_AUTH_METHOD` 非空且既不是 `'oauth-personal'` 也不是 `'oauth-business'`（如 Vertex / API Key 等无配额窗口方式），直接返回 `false`。
    - 否则检查 `account.credentialPaths` 中是否存在非空常规文件（`stat.isFile() && stat.size > 2`）。
  - **Codex**：
    - 读取 `account.credentialPaths`（`auth.json`），解析 JSON 并确认存在非空 `tokens.access_token` 或 `tokens.refresh_token`（纯 API Key 且无 OAuth token 不算可查配额的已登录账号，除非未来另有需求；当前与 `probeCodex` 一致）。
  - **Claude Code**：
    - 读取 `account.credentialPaths`（`.credentials.json`），解析 JSON 并确认存在非空 `claudeAiOauth.accessToken` 或 `claudeAiOauth.refreshToken`。
  - **OpenCode**：
    - 满足以下任一条件返回 `true`：`account.origin === 'manual'` 且加密文件 `opencode-go-key` 存在；`account.credentialPaths` 中的 `auth.json` 包含非空 `'opencode-go'.key`（或文件 `size > 2`）；`account.origin === 'native'` 且 `Boolean(process.env.OPENCODE_API_KEY?.trim())`；`hasOpenCodeDbCredential(account.dataDir)` 为 `true`。
- 调整 `list()` 与 `listInternal()` 的返回口径：
  - 读取 `hiddenSet = new Set(config.hiddenAccountIds)`；
  - 对自动发现账号（`account.origin === 'native' || account.origin === 't3'`）：
    - 仅保留 **`hasCredential === true`** 的条目（无凭证原生历史目录、`antigravity-vertex`、已退出的空 `.claude` 目录全部不再出现在「账号管理」和「限制」探测队列中）；
    - 将所有 `hasCredential === true` 但命中的 `hiddenSet.has(account.id)` 计入 `hiddenAutoCount`，并从可见列表与 `listInternal()` 中排除；
  - 对手动 / 应用内账号（`account.origin === 'manual'`）：
    - 始终留在列表中（除非用户执行删除）。
- 注意 `listInternal()` 的返回类型继续保持 `DiscoveredAccount[]`，供 `createLimitsService` 在启动、`refresh()`、`hydrate()`、`consumeResetCredit()` 中直接使用。

  - 将 `id` 去重追加到 `config.hiddenAccountIds`，并清理 `config.accountPreferences[id]`；

## 3. 应用内直接登录（本地 CLI OAuth + 隔离多账号目录）

面向分发场景的核心体验：别人打开 UsageDashboard 时，第 1 步优先由本地已登录扫描零配置带出账号；若需新增或切换其他账号，可在「账号管理 → 添加账号」中直接拉起浏览器完成 OAuth 登录，凭证以隔离目录存放在应用私有 `userData` 中，支持同一提供方多账号并存且绝不覆盖全局 `~/.codex`、`~/.claude`、`~/.gemini`。

### 3.1 存储隔离模型与默认命名
- **两类应用私有隔离路径（均位于 `app.getPath('userData')` 下）**：
  1. `credentialRoot = join(userData, 'accounts', accountId)`：用于存放由 `safeStorage` 加密的单文件凭证（Antigravity 的 `antigravity-oauth-token` / `acp_token.json`；OpenCode 的 `opencode-go-key`）。
  2. `profileRoot = join(userData, 'profiles', accountId)`：用于存放 CLI 工具自身直接读写的隔离配置目录（Codex 的 `CODEX_HOME`；Claude Code 的 `CLAUDE_CONFIG_DIR`）。
     - `profiles/` 与 `accounts/` 同级存放后，[service.ts](../../src/main/accounts/service.ts) 中的 `readCredential(file)` 仅对 `credentialRoot` 下文件走 `decrypt()`，对 `profiles/` 下的 `.json` 直接按 UTF-8 JSON 读取；同时 `probeCodex`、`codexResetCredit`、`probeClaude` 也能以 `account.dataDir`（位于 `userData/profiles/<id>`，满足 `safeCliDirectory`）安全拉起 `codex app-server` / `claude` CLI 自动刷新过期 token。
- **默认显示名防重名**：
  - 若用户在表单中未填写「显示名」，默认取提供方名称（`Antigravity` / `Codex` / `Claude Code` / `OpenCode`）；
  - 若当前可见账号中已存在同名显示名，自动按 `"{base} 2"`、`"{base} 3"` 递增编号，确保同一提供方登录多个账号时在限制页与气泡中清晰可辨。

### 3.2 新增共享类型与 IPC（`src/shared/limitsTypes.ts`、`src/shared/ipc.ts`、`src/preload/index.ts`、`src/main/ipc.ts`）
1. **`src/shared/limitsTypes.ts`**：

2. **`src/shared/ipc.ts` 与 `src/preload/index.ts`**：
   - `usageChannels` 新增：
     - `accountLoginState: 'usage:account-login-state'`
     - `startAccountLogin: 'usage:start-account-login'`
     - `submitAccountLoginCode: 'usage:submit-account-login-code'`

3. **外链打开白名单校验（`openExternalUrl`）**：
   - 仅允许 `https:` 协议且主机名严格属于：
     `accounts.google.com`、`auth.openai.com`、`chatgpt.com`、`claude.ai`、`console.anthropic.com`、`github.com`；
   - 拒绝包含空白字符、自定义用户凭据或非上述主机名的 URL，通过 `shell.openExternal(parsed.toString())` 打开。

### 3.3 主进程登录管理器（`src/main/accounts/loginManager.ts`）
- **状态机与并发控制**：
  - 全局同一时间最多允许 1 个活跃 OAuth 登录流程（新发起前若仍有运行中的流程，先中止旧流程并清理未提交目录）。
  - 单次流程总超时 `5 分钟`（`300_000 ms`）；超时或退出应用（`app.on('before-quit')` 调用 `loginManager.stop()`）时强制杀掉子进程树（Windows 下复用/抽离 `killWindowsTree` + `SIGKILL`）并删除未完成的临时/隔离目录。
  - **严禁**在任何状态消息或日志中输出 `access_token`、`refresh_token`、`code`、授权回调 URL 或用户邮箱。
- **各提供方登录实现细节**：
  1. **Antigravity（`agy acp --login` + `safeStorage` 加密落盘）**：
     - 参考 `T3 Code` `AntigravityDriver.ts` L422–L494 与 `antigravityAuthSupport.ts` L230–L234、L575–L644：
     - 通过 `resolveAgyCli({ scanT3: config.scanT3 })` 查找 `agy` 可执行文件；未找到时立即返回 `phase: 'failed'`，`message: '未检测到 Antigravity CLI（agy），请先安装 Antigravity 后再登录。'`。
     - 创建临时根目录 `tempRoot = await mkdtemp(join(tmpdir(), 'usage-agy-login-'))` 及 `acpDir = join(tempRoot, 'antigravity-acp')`，写入 `join(acpDir, 'settings.json')` = `{"auth":{"type":"oauth-personal"}}\n`。
     - 构造清洁环境变量（从白名单复制 `PATH`、`SYSTEMROOT`、`WINDIR`、`COMSPEC`、`PATHEXT`、`LANG`、`LC_ALL`、`HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY`、`SSL_CERT_FILE`、`SSL_CERT_DIR`，移除 `DISPLAY` / `WAYLAND_DISPLAY` / `ELECTRON_RUN_AS_NODE`，注入 `HOME`/`USERPROFILE`/`APPDATA`/`LOCALAPPDATA`/`TEMP`/`TMP`/`GEMINI_HOME` = `tempRoot`，以及 `SSH_CONNECTION: '127.0.0.1 0 127.0.0.1 0'`、`AGY_ACP_FORCE_FILE_STORAGE: '1'`、`AGY_CLI_DISABLE_AUTO_UPDATE: '1'`，使 `agy` 强制输出 Google 授权链接并把 token 写入文件而非覆盖全局 keyring）。
     - 启动子进程：
       `spawn(executable, ['acp', '--gemini-dir', tempRoot, '--app-data-dir', 'antigravity-acp', '--disable-telemetry', '--include-default-customizations=false', '--login'], { cwd: tempRoot, env, shell: false, windowsHide: true, stdio: ['pipe', 'pipe', 'pipe'] })`
     - 监听 stdout 按行扫描 `https://accounts.google.com/`：
       - 严格校验 URL：`origin === 'https://accounts.google.com'`、`response_type === 'code'`、非空单值 `state`（长度 1..512，无空白）、`redirect_uri === 'https://antigravity.google/oauth-callback'`；
       - 校验通过后保存待核验参数（`redirectUri`、`state`），自动调用一次 `openExternal(url)` 打开浏览器，同时推送 `phase: 'waiting_code'` 与 `authorizationUrl`。
     - 用户在前端提交授权码/回调 URL（`submitAccountLoginCode(flowId, raw)`）：
       - 校验 `raw.trim()` 为 `^[\w./~-]{1,2048}$` 授权码，或为 `origin + pathname === pending.redirectUri`、单值 `state === pending.state` 且非空 `code` 的完整回调 URL（拒绝任何换行与多行注入）；
       - 向 `child.stdin` 写入 `${validated}\n`，推送 `phase: 'verifying'`；
     - `child` 以退出码 `0` 结束：
       - 按顺序尝试读取 `join(acpDir, 'antigravity-oauth-token')` 与 `join(acpDir, 'acp_token.json')` 并用 schema 校验非空有效凭证；
       - 通过 `safeStorage` 加密写入 `join(userData, 'accounts', accountId, filename)`（复用或抽取 `createAccountService` 中的加密保存方法 `addManagedAccount`）；
       - 写入 `config.accounts`，触发 `onCommitted()`（刷新 `limits.accountsChanged` + `limits.refresh()`），在 `finally` 中安全删除 `tempRoot`（`unlink` + `rm(..., { recursive: true, force: true, maxRetries: 10, retryDelay: 200 })`），推送 `phase: 'succeeded'`。
  2. **Codex（`codex app-server` JSON-RPC `account/login/start`）**：
     - 通过 `resolveCli('codex')` 查找本机 `codex.exe`；未找到时返回 `phase: 'failed'`，`message: '未检测到 Codex CLI（codex），请先安装 Codex CLI 后再登录。'`。
     - 在 `userData/profiles/<accountId>` 创建隔离目录并预写 `config.toml`：`cli_auth_credentials_store = "file"\n`（确保落盘到该隔离目录的 `auth.json` 而非覆盖系统 keyring）。
     - 启动子进程：`spawn(executable, ['-c', 'cli_auth_credentials_store="file"', 'app-server'], { cwd: profileDir, env: cliEnvironment('CODEX_HOME', profileDir), shell: false, windowsHide: true, stdio: ['pipe', 'pipe', 'pipe'] })`（`cliEnvironment` 补含 `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/`NO_PROXY` 以便网络代理可用，同时不继承全局 `OPENAI_API_KEY`）。
     - 按行收发 NDJSON JSON-RPC：
       1. 发送 `{"id":1,"method":"initialize","params":{"clientInfo":{"name":"usage-dashboard","version":"..."}}}`；
       2. 收到 `id === 1` 成功后发送 `{"method":"initialized"}` 与 `{"id":2,"method":"account/login/start","params":{"type":"chatgpt"}}`；
       3. 收到 `id === 2` 返回 `{ type: 'chatgpt', loginId, authUrl }`：校验 `authUrl` 为 `https:` 且域名属 `auth.openai.com` / `chatgpt.com`，自动调用一次 `openExternal(authUrl)`，推送 `phase: 'waiting_browser'` 与 `authorizationUrl`；
       4. 监听服务端通知 `method === 'account/login/completed'`：
          - 若 `params.success === true` 且 `join(profileDir, 'auth.json')` 存在非空 `tokens.access_token`：关闭子进程，把 `{ id: accountId, provider: 'codex', displayName, dataDir: profileDir }` 写入 `config.accounts`，调用 `onCommitted()`，推送 `phase: 'succeeded'`；
          - 若 `params.success === false`：清理子进程与 `profileDir`，推送 `phase: 'failed'`（`message: params.error?.trim() || 'Codex 登录未完成，请重试。'`）。
     - 取消流程时先尽量发送 `{"id":3,"method":"account/login/cancel","params":{"loginId"}}`，再终止进程树并清理 `profileDir`。
  3. **Claude Code（`claude auth login --claudeai`）**：
     - 通过 `resolveCli('claude')` 查找本机 `claude.exe`；未找到时返回 `phase: 'failed'`，`message: '未检测到 Claude Code CLI（claude），请先安装 Claude Code 后再登录。'`。
     - 在 `userData/profiles/<accountId>` 创建隔离目录；构造清洁环境变量：以 `cliEnvironment('CLAUDE_CONFIG_DIR', profileDir)` 为基础，追加 `COMSPEC`、`PATHEXT`、`HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY`、`DISABLE_AUTOUPDATER: '1'`，显式剔除 `CLAUDECODE`、`ELECTRON_RUN_AS_NODE`、`ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`。
     - 启动 `spawn(executable, ['auth', 'login', '--claudeai'], { cwd: profileDir, env, shell: false, windowsHide: true, stdio: ['pipe', 'pipe', 'pipe'] })`。
     - **避免重复弹两个浏览器标签页**：Windows 下 `claude auth login` 会自行拉起默认浏览器，因此主进程**不**自动调用 `openExternal`；仅从 stdout/stderr 提取符合白名单（`claude.ai` / `console.anthropic.com`）的 `https://` 授权链接写入 `authorizationUrl`，推送 `phase: 'waiting_browser'`，供用户在浏览器未自动弹出时手动点击「打开授权页面」。
     - 进程退出码为 `0` 时，读取校验 `join(profileDir, '.credentials.json')` 含有非空 `claudeAiOauth.accessToken`（或 `refreshToken`）：写入 `config.accounts`（`dataDir: profileDir`），触发 `onCommitted()`，推送 `phase: 'succeeded'`；否则清理 `profileDir` 并推送 `phase: 'failed'`。
  4. **OpenCode**：
     - 保持使用表单内置 `Go API Key` 密码输入框提交给 `addManualAccount({ provider: 'opencode', displayName, mode: 'apiKey', apiKey })`，无需调用外部浏览器。

### 4.3 主进程更新服务（`src/main/updater.ts`）与退出协同（`src/main/index.ts`）
- **运行模式识别**：
  - `portable`：`app.isPackaged && Boolean(process.env.PORTABLE_EXECUTABLE_FILE)`（Windows 单文件便携版运行在随机 `%TEMP%` 解压目录，无法由 `NsisUpdater` 原地覆盖自己）；

  - `development`：`!app.isPackaged`（若设置了测试环境变量 `USAGE_DASHBOARD_UPDATE_URL` 则允许走模拟测试链路）。
- **NSIS 安装版路径（`electron-updater` `autoUpdater`）**：
  - 配置：`autoUpdater.autoDownload = false`、`autoUpdater.autoInstallOnAppQuit = true`、`autoUpdater.allowDowngrade = false`；若存在环境变量 `USAGE_DASHBOARD_UPDATE_URL`，通过 `autoUpdater.setFeedURL({ provider: 'generic', url })` 指向本地测试源；
  - 绑定事件：`checking-for-update`、`update-available`、`update-not-available`、`download-progress`（提取 `Math.round(progress.percent)`）、`update-downloaded`、`error`；
  - **`silent` 启动/后台轮询 vs 手动检查区分**：
    - `silent = true`（启动后延迟 `10s` 首检 + 每 `4h` 定时复检，退出时清理定时器）：若发生 `404` / `No published versions` / 断网 / 超时错误，**静默退回 `status: 'idle'`**，不弹报错、不扰民；
    - `silent = false`（用户点击托盘或面板内「检查更新」）：若 GitHub Release 尚未创建或返回 404，收敛为友好提示（`status: 'up-to-date'` 或 `'idle'`，文案 `暂未检测到已发布的新版本`）；若为网络异常，设 `status: 'error'` 并给出 `检查更新失败，请检查网络后重试`；
  - **`installUpdate()` 与窗口关闭到托盘协同（关键修复点）**：
    - 在 [src/main/index.ts](../../src/main/index.ts) 中抽离 `prepareQuitForUpdate(): Promise<void>` 并传给更新器回调：
      1. 设置 `quitting = true`（防止 `window.on('close')` 截获并最小化到托盘导致更新安装器等待主进程退出而卡死）；
      2. 调用 `limits.stop()`、`loginManager.stop()`；
      3. 等待 `waitForAntigravityRenewals()`；
      4. 设置 `cleaned = true`（防止 `app.on('before-quit')` 再次 `preventDefault()`），销毁 `tray`；
      5. 在 `setImmediate(() => autoUpdater.quitAndInstall(false, true))` 中拉起静默覆盖安装并重启应用。
- **Portable 便携版路径（GitHub Releases API + 安全下载）**：
  - 优先从 `join(process.resourcesPath, 'app-update.yml')` 解析 `owner` / `repo`（兜底 `'Henry-916'` / `'UsageDashboard'`）；支持 `USAGE_DASHBOARD_UPDATE_URL` 覆盖用于本地 HTTP 模拟回归；
  - 请求 `https://api.github.com/repos/${owner}/${repo}/releases/latest`（带 `Accept: application/vnd.github+json`、`User-Agent: UsageDashboard/${currentVersion}`、`redirect: 'error'`）；
  - 使用严格语义版本比较 `compareSemver(latestVersion, currentVersion)`（剥离前导 `v` 与预发布比较）；
  - 在 `assets` 中查找 `/portable.*x64\.exe$/i` 资产（校验文件名合法且 `browser_download_url` 为 `https:` 并属于 `github.com` / `objects.githubusercontent.com` 或测试 URL）；
  - `downloadUpdate()`：若存在便携版资产 `browser_download_url`，使用 `fetch` + `AbortSignal` 流式下载到 `join(app.getPath('downloads'), `${assetName}.part`)`（防路径穿越与中途断裂残留），实时上报 `downloadPercent`，校验写完后原子 `rename` 为 `join(app.getPath('downloads'), assetName)`，状态转为 `downloaded` 并记录 `downloadedFile`；若无直链资产，通过校验后的 `releaseUrl` 打开系统浏览器；
